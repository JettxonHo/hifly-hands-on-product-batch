## 一、正式产品定位

当前项目不能继续只被定义为：

```text
飞影网页批量自动化工具
```

正式产品定位升级为：

```text
面向电商运营团队的 AI 数字人内容生产 SaaS。
从商品与营销目标、文案生成与质检、数字人/声音/背景素材，
到视频方案审核、批量生产、成片质检、交付与发布管理，
形成完整的数字人内容生产工作流。
飞影只是底层视频生成供应商之一。
```

现有项目已经建设的可靠执行能力必须保留，但逐步下沉为：

```text
Local Execution Agent / Provider Execution Engine
```

上层重新建设：

```text
产品模型
用户流程
运营工作台
素材资产中心
视频方案
商业 SaaS 外观
```

**不得推翻现有可靠执行内核。**

## 二、目标用户与角色

### 1. 电商运营（核心角色）

核心工作：

- 创建商品内容项目
- 上传商品和卖点
- 生成文案
- 选择人物、声音和背景
- 创建视频方案
- 发起生产
- 处理失败任务
- 下载作品和发布物料

### 2. 内容审核人

核心工作：

- 审核文案
- 审核品牌表达
- 审核数字人和场景方案
- 审核成片
- 退回修改
- 批准交付

### 3. 团队管理员

核心工作：

- 管理成员与权限
- 管理品牌规范
- 管理数字人授权
- 管理 Provider 连接
- 查看任务用量和成本
- 查看生产成功率

### 4. 技术或本地执行器管理员

核心工作：

- 安装和配对 Local Agent
- 维护飞影登录态
- 处理验证码
- 查看执行器健康状态
- 查看技术日志和失败证据

第一版不要求立刻实现完整 RBAC，但领域模型和页面规划必须为这些角色留出清晰边界。

## 三、用户价值

运营人员购买的不是网页自动化，而是**稳定、可审核、可批量复制的数字人内容生产结果**：

- 把「商品 + 营销目标」变成「可发布的数字人视频」；
- 文案、人物、声音、背景、成片全程可审核、可退回、可复用；
- 批量生产有看板、有质检、有证据、有交付；
- 失败可定位、可人工处理、可重试，不丢失工作。

## 四、核心产品原则

### 原则 1：用户购买的是生产结果，不是网页自动化

运营人员不应该理解：

- Playwright
- Fastify
- batch.json
- executor
- committed snapshot
- operation queue
- portable path
- execution lock
- capture HTTP

运营人员应该理解：

```text
创建项目
→ 上传商品
→ 生成并审核文案
→ 选择数字人、声音和背景
→ 确认视频方案
→ 批量生成
→ 质检
→ 下载与发布
```

技术状态仍然保留，但应放在任务详情、诊断页面和本地执行器页面中，而不是成为主要产品语言。

### 原则 2：飞影是 Provider，不是整个产品

产品上层必须避免和飞影页面结构永久绑定。长期架构：

```text
AI 数字人内容生产 SaaS
        ↓
标准化视频方案与生产任务
        ↓
Provider Adapter
├── Hifly Playwright Adapter
├── Hifly API Adapter（如未来正式开放并获得权限）
├── 影刀 RPA Adapter（可选）
├── 其他数字人平台 Adapter
└── 其他视频模型 API Adapter
```

**不得在上层产品模型中直接使用飞影按钮文案、页面 selector 或具体网页步骤作为领域概念。**

### 原则 3：云端控制面与本地执行 Agent 分离

```text
云端 SaaS Control Plane
├── 用户、组织、权限
├── 项目与商品
├── 文案与审核
├── 数字人/声音/背景资产
├── 视频方案
├── 生产任务编排
├── 用量与商业信息
└── 状态同步

本地或 VPS Local Agent
├── Playwright 浏览器执行
├── 飞影登录态
├── 本地文件访问
├── 上传与下载
├── 验证码和人工接管
├── 失败证据
└── Provider Adapter
```

**不得把长时间 Playwright 任务直接塞入不适合长任务的 Serverless/Workers 请求生命周期。**

### 原则 4：跨平台是产品竞争力

核心 Local Agent 应优先支持：

- macOS
- Windows
- 后续 Linux/VPS

不得把产品主链路绑定到只有 Windows 能稳定运行的低代码 RPA 工具。影刀可以作为可选 Adapter，但不能成为产品领域模型和核心执行协议的唯一基础。

### 原则 5：不自研数字人基础模型

产品要提供「数字人产品能力」，但第一阶段不训练自己的数字人模型。

第一阶段通过 Provider 完成：

- 公共数字人选择
- 照片数字人
- 视频数字人复刻
- AI 生成人物
- 声音克隆
- 文本转语音
- 对口型
- 视频换背景
- 手里有货
- 实景口播
- 双人播客

上层 SaaS 负责：

- 资产建模
- 用户选择
- 参数配置
- 任务编排
- 状态跟踪
- 结果登记
- 审核和交付

**不得在文档中假设所有飞影能力都已经存在正式 API。** 需要把「已确认可自动化」「待技术调研」「待账号权限确认」分开记录（见 [PROVIDER_AND_AGENT_ARCHITECTURE.md](PROVIDER_AND_AGENT_ARCHITECTURE.md)）。

### 原则 6：敏感资产授权与保护底线

用户照片、视频、声音和数字人复刻源素材属于**敏感资产**：

1. 未记录有效授权，不得：创建数字人、克隆声音、上传 Provider、创建对口型任务、创建生产任务；
2. 授权失效、撤销或资产 disabled 后：新任务 Preflight 必须 fail-closed，不得继续创建新的 Provider 任务；
3. 资产的创建、使用、撤销、删除需要审计留痕；
4. 云端和 Local Agent 只处理任务需要的最小数据；
5. 普通运营不能通过修改前端字段绕过授权状态；
6. Provider Adapter 在真实上传前必须重新校验授权状态。

具体授权材料形式、保留期限、删除时限和法律文本仍为开放问题（见 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) 的 Q-007 / Q-008），不得擅自决定。本原则的正式决策记录为 [DECISION_LOG.md](DECISION_LOG.md) 的 D-011。

## 五、五阶段核心生产流程

这是产品最重要的主流程，定义为项目内部统一阶段导航：

```text
1. 商品与目标
2. 文案与质检
3. 人物与素材
4. 视频方案
5. 生成与交付
```

### 阶段一：商品与生产目标

用户创建的是「内容生产项目」，不是直接创建技术 batch。项目需要表达：

- 项目名称、品牌、目标平台、内容目标
- 商品数量、计划视频数量、每商品方案数量
- 视频形式、目标用户、内容风格
- 语言、期望时长、比例
- 品牌禁用词、品牌表达规则
- 交付日期、项目成员

示例：

```text
项目：8 月小红书防晒霜种草
目标平台：小红书
内容形式：数字人口播带货
商品数：10
每商品方案数：3
计划视频数：30
时长：20～35 秒
目标人群：20～30 岁通勤女性
风格：真实分享、轻种草
```

视频类型必须作为业务卡片呈现，而不是底层执行器名称：

- 手里有货
- 数字人口播
- 照片说话
- 对口型
- 实景口播
- 商品讲解
- 双人播客
- 自定义方案

第一版可以只真正执行少数类型，但产品模型必须允许后续扩展。

### 阶段二：文案生成与内容质检

每件商品不能只有一个 selling_points 和单条脚本，应建模为：

```text
商品
└── 内容方案
    ├── 内容角度
    ├── 开场钩子
    ├── 完整口播文案
    ├── 卖点覆盖
    ├── 行动引导
    ├── 预计时长
    ├── 目标平台
    ├── 质检结果
    ├── 版本
    └── 审核状态
```

内容角度至少支持：痛点切入、场景切入、对比测评、好物分享、成分解析、用户体验、限时促销、情绪价值、知识科普。一件商品可生成多个**真正不同**的内容角度，不是简单同义词改写。

文案工作流：

```text
草稿 → 待质检 → 需修改 → 待人工确认 → 已确认
```

功能规划：生成多个版本、重新生成全文、只重写开头、只修改某一句、缩短或扩写、改成更口语化、改成指定平台风格、版本对比、固定当前版本、批量审核、自动修复质检问题。

质检维度至少规划：开场吸引力、卖点覆盖、逻辑完整度、口语自然度、字数与预计时长、重复表达、行动引导、夸张宣传、禁用词、敏感表达、平台适配、品牌规范。

质检结果不能只有通过/失败，应包含**结构化分数、问题位置和修复建议**。只有「已确认」的文案才能进入正式视频方案。

### 阶段三：数字人、声音、背景与素材工作室

本阶段统一管理所有可复用生产资产。

**数字人资产**来源类型：公共数字人、用户上传照片创建、用户上传视频复刻、AI 生成人物、企业专属数字人、Provider 已有数字人引用。

数字人资产字段规划：名称、头像与预览、来源、Provider、Provider 内部引用、创建状态、授权状态、性别和年龄风格、适用品类、坐姿/站姿、正面/侧面/全身、可用视频类型、默认声音、标签、创建者、所属组织。**不得让普通用户看到本地文件路径作为主要信息。**

**声音资产**来源类型：公共音色、用户克隆声音、上传录音、文本转语音、Provider 音色引用。配置：语言、方言、性别风格、情绪、语速、音调、试听、授权状态、适用数字人。**数字人与声音不得永久硬绑定**，同一个数字人可以搭配多个声音。

**背景与场景资产**来源类型：纯色、家居、厨房、办公室、商场、户外、直播间、品牌定制、用户上传、AI 生成背景、原视频背景、Provider 模板。场景字段规划：横屏/竖屏、适用品类、画面亮度、背景复杂度、人物站位、商品展示区域、Logo 安全区域、推荐字幕位置、标签。

**其他素材**：商品图片、人物原图、原始视频、音频、Logo、字体、字幕模板、封面模板、品牌视觉规范、参考视频。

**对口型**应同时被定义为：一项 Provider 能力、一种视频生产模式、视频方案中的一个可配置步骤。输入：人物图片或视频、文案或音频、声音、背景、输出比例、字幕、是否保留原背景。输出：Provider 任务、对口型视频、质检结果、最终作品资产。

### 阶段四：视频方案与生成前审核

视频方案是内容与执行之间的**正式业务边界**。一个视频方案至少包含：

```text
商品、内容文案版本、视频类型、数字人、声音、背景/场景、
商品图片、人物图片或视频、字幕模板、封面模板、画面比例、
目标时长、Provider、生成参数、审核状态
```

示例卡片：

```text
防晒霜方案 01
文案：通勤防晒痛点版
人物：小雅·室内坐姿
声音：自然女声 02
背景：明亮梳妆台
视频形式：手里有货
比例：9:16
预计时长：27 秒
字幕：品牌简洁模板
状态：待审核
```

运营人员操作：预览所有输入、更换人物、更换声音、更换背景、修改文案、复制方案、创建变体、批量应用配置、标记为已审核、退回上一阶段。

审核流：

```text
草稿 → 待审核 → 需修改 → 已批准 → 已排入生产
```

发起生产前必须有 Preflight：商品素材是否完整、文案是否已确认、数字人是否可用、声音是否可用、授权是否完整、Provider 登录状态、Local Agent 在线状态、输出目录和磁盘状态、预计任务数、预计 Provider 消耗、风险提示、失败重试策略。

**内部 pointBudget 不得作为 SaaS 用户术语。** SaaS 用户看到的是任务数、预计用量、套餐余量和 Provider 成本提示。

### 阶段五：批量生产、质检、作品与交付

生产看板采用运营语言：待生成、生成素材中、素材待确认、视频生成中、下载中、已完成、需人工处理、已取消。

点击任务后再显示：当前阶段、执行日志、重试次数、Provider 任务 ID、本地执行器、失败原因、截图证据、产物、技术状态。

**现有底层状态机可以保留，但需要增加业务状态映射层。**

成片质检——第一阶段基础质检：文件存在、文件可播放、分辨率、比例、时长、音轨存在、黑屏检测、字幕存在、方案资产匹配、文案与音频时长匹配。后续 AI 质检：口型同步、人脸异常、商品变形、画面闪烁、字幕错误、敏感内容、Logo 遮挡、背景不一致。

作品库和交付——用户可以：预览作品、标记通过/退回、批量下载、按商品打包、下载文案、下载封面、下载审核表、导出项目交付包、标记已发布、记录发布平台和链接、记录表现数据。

## 六、商业 SaaS 表现

### 首页仪表盘规划

本月生成视频数、成功率、生产中任务、待审核文案、待审核视频方案、待处理失败、已启用数字人数、最近项目、套餐或任务余量、预计节省时间。

### 首次使用新手引导

```text
1. 创建第一个项目
2. 上传一个商品
3. 生成三版文案
4. 选择数字人、声音和背景
5. 生成第一条视频
```

### 模板中心规划

模板方向：小红书护肤种草、抖音零食带货、淘宝商品讲解、本地生活探店、知识口播、企业介绍、照片说话、双人访谈。

模板可预设：内容结构、时长、视频类型、数字人、声音、背景、字幕、Provider、质检规则。

## 七、MVP 与长期愿景

- **第一阶段（MVP 方向）**：即使部分步骤仍需人工，也能完整走完五阶段产品链路；主导航克制（首页/项目/素材中心/生产任务/作品库/设置）；飞影多能力按优先级分批接入；本地执行内核继续承担真实执行。详见 [DELIVERY_ROADMAP.md](DELIVERY_ROADMAP.md) 的 Phase 0～4。
- **长期愿景**：云端 SaaS Control Plane + 多 Local Agent + 多 Provider Adapter 的商业化数字人内容生产平台，含组织权限、用量计费、模板市场、发布管理与数据复盘。
- MVP 与长期愿景之间不允许跳级：不一次性开发所有 SaaS 功能，不先做支付系统。

## 八、非目标（本轮与产品边界）

- 不在本轮开发任何页面或 API
- 不在本轮执行真实飞影任务
- 不执行 MULTI-002
- 不消耗飞影积分
- 不训练数字人模型
- 不承诺所有飞影能力都有正式 API
- 不把现有 Playwright 内核删除
- 不立即把所有数据迁移到云数据库
- 不一次性开发所有 SaaS 功能
- 不先做支付系统
- 不把影刀设为唯一执行器
- 不因产品重构而降低现有安全、幂等、原子写、路径和 CI 标准
- 不开始 CORE-002 或其他非文档实现
- 不合并 PR #41
- 不修改 PR #41 分支
