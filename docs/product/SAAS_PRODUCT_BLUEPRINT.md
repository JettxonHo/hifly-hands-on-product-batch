## 一、正式产品定位

当前项目不能继续只被定义为：

```text
飞影网页批量自动化工具
```

正式产品定位升级为：

```text
面向电商运营团队的 AI 数字人内容生产 SaaS。
从商品与营销目标、文案生成与质检、数字人/声音/背景素材，
到视频方案审核、批量生产、成片质检、交付与发布管理，
形成完整的数字人内容生产工作流。
飞影只是底层视频生成供应商之一。
```

产品边界（对应 D-014 / D-015 / D-016）：

- **企业内部平台**：第一批目标用户是企业内部的电商运营、内容生产、内容审核和管理团队；产品是企业内部 AI 数字人内容生产平台，不是面向公众自助购买的通用消费者 SaaS（D-014）。
- **Cloud-first**：第一版是可以通过浏览器访问的 Cloud-first Web Control Plane，默认部署目标为腾讯云；正式表述为 Tencent Cloud first，不是 Tencent Cloud only（D-015）。
- **单企业/单组织 MVP**：第一版优先服务单一企业、单一组织，但领域模型保留 Organization 边界（D-014 / D-015）。
- **第一版企业登录**：管理员预创建账号、工作邮箱和密码登录、首次登录强制修改临时密码、登录后自动进入唯一组织；不开放公众注册、组织选择、多组织切换，不建设手机号/短信/企业微信登录，自助密码找回后置（D-024）。
- **不建设支付、套餐和账单**：不建设支付、套餐、订阅、账单、充值、余额、优惠券、续费、面向客户的自动计费；保留企业内部用量、成本、权限和审计（D-016）。
- **人物步骤双入口**：人物步骤统一表达为「创建新人物或选择现有人物」（D-017）。
- **文案为 SaaS 自有能力**：文案生成、版本管理、品牌规则、质检和审核属于 SaaS 自有业务能力（D-019）。
- **MVP 平台默认凭证**：MVP 使用平台默认 LLM 凭证；企业 BYOK 进入管理员高级设置（D-020）。
- **腾讯云与飞影都可替换**：腾讯云和飞影都属于可替换基础设施/Provider，不进入领域模型（D-015 / D-002）。

现有项目已经建设的可靠执行能力必须保留，但逐步下沉为：

```text
Local Execution Agent / Provider Execution Engine
```

上层重新建设：

```text
产品模型
用户流程
运营工作台
素材资产中心
视频方案
企业内部平台体验
```

**不得推翻现有可靠执行内核。**

## 二、目标用户与角色

第一批目标用户是**企业内部的电商运营、内容生产、内容审核和管理团队**（D-014）；产品是企业内部 AI 数字人内容生产平台，不是面向公众自助购买的通用消费者 SaaS。

### 1. 电商运营（核心角色）

核心工作：

- 创建商品内容项目
- 上传商品和卖点
- 生成文案
- 选择人物、声音和背景
- 创建视频方案
- 发起生产
- 处理失败任务
- 下载作品和发布物料

### 2. 内容审核人

核心工作：

- 审核文案
- 审核品牌表达
- 审核数字人和场景方案
- 审核成片
- 退回修改
- 批准交付

### 3. 团队管理员

核心工作：

- 管理成员与权限
- 管理品牌规范
- 管理数字人授权
- 管理 Provider 连接
- 查看任务用量和成本
- 查看生产成功率

### 4. 技术或本地执行器管理员

核心工作：

- 安装和配对 Local Agent
- 维护飞影登录态
- 处理验证码
- 查看执行器健康状态
- 查看技术日志和失败证据

第一版不要求立刻实现完整 RBAC，但领域模型和页面规划必须为这些角色留出清晰边界。

## 三、用户价值

运营人员购买的不是网页自动化，而是**稳定、可审核、可批量复制的数字人内容生产结果**：

- 把「商品 + 营销目标」变成「可发布的数字人视频」；
- 文案、人物、声音、背景、成片全程可审核、可退回、可复用；
- 批量生产有看板、有质检、有证据、有交付；
- 失败可定位、可人工处理、可重试，不丢失工作。

## 四、核心产品原则

### 原则 1：用户购买的是生产结果，不是网页自动化

运营人员不应该理解：

- Playwright
- Fastify
- batch.json
- executor
- committed snapshot
- operation queue
- portable path
- execution lock
- capture HTTP

运营人员应该理解：

```text
创建项目
→ 上传商品
→ 生成并审核文案
→ 选择数字人、声音和背景
→ 确认视频方案
→ 批量生成
→ 质检
→ 下载与发布
```

技术状态仍然保留，但应放在任务详情、诊断页面和本地执行器页面中，而不是成为主要产品语言。

### 原则 2：飞影是 Provider，不是整个产品

产品上层必须避免和飞影页面结构永久绑定。长期架构：

```text
AI 数字人内容生产 SaaS
        ↓
标准化视频方案与生产任务
        ↓
Provider Adapter
├── Hifly Playwright Adapter
├── Hifly API Adapter（API 文档已确认；启用需账号权限、真实调用和 Adapter 验证）
├── 影刀 RPA Adapter（可选）
├── 其他数字人平台 Adapter
└── 其他视频模型 API Adapter
```

**不得在上层产品模型中直接使用飞影按钮文案、页面 selector 或具体网页步骤作为领域概念。**

### 原则 3：云端控制面与本地执行 Agent 分离

```text
云端 SaaS Control Plane
├── 用户、组织、权限
├── 项目与商品
├── 文案与审核
├── 数字人/声音/背景资产
├── 视频方案
├── 生产任务编排
├── 内部用量与治理信息
└── 状态同步

本地或 VPS Local Agent
├── Playwright 浏览器执行
├── 飞影登录态
├── 本地文件访问
├── 上传与下载
├── 验证码和人工接管
├── 失败证据
└── Provider Adapter
```

**不得把长时间 Playwright 任务直接塞入不适合长任务的 Serverless/Workers 请求生命周期。**

### 原则 4：跨平台是产品竞争力

核心 Local Agent 应优先支持：

- macOS
- Windows
- 后续 Linux/VPS

不得把产品主链路绑定到只有 Windows 能稳定运行的低代码 RPA 工具。影刀可以作为可选 Adapter，但不能成为产品领域模型和核心执行协议的唯一基础。

### 原则 5：不自研数字人基础模型

产品要提供「数字人产品能力」，但第一阶段不训练自己的数字人模型。

第一阶段通过 Provider 完成：

- 公共数字人选择
- 照片数字人
- 视频数字人复刻
- AI 生成人物
- 声音克隆
- 文本转语音
- 对口型
- 视频换背景
- 手里有货
- 实景口播
- 双人播客

上层 SaaS 负责：

- 资产建模
- 用户选择
- 参数配置
- 任务编排
- 状态跟踪
- 结果登记
- 审核和交付

**不得在文档中假设所有飞影能力都已经存在正式 API。** 需要把「已确认可自动化」「待技术调研」「待账号权限确认」分开记录（见 [PROVIDER_AND_AGENT_ARCHITECTURE.md](PROVIDER_AND_AGENT_ARCHITECTURE.md)）。

### 原则 6：敏感资产授权与保护底线

用户照片、视频、声音和数字人复刻源素材属于**敏感资产**：

1. 未记录有效授权，不得：创建数字人、克隆声音、上传 Provider、创建对口型任务、创建生产任务；
2. 授权失效、撤销或资产 disabled 后：新任务 Preflight 必须 fail-closed，不得继续创建新的 Provider 任务；
3. 资产的创建、使用、撤销、删除需要审计留痕；
4. 云端和 Local Agent 只处理任务需要的最小数据；
5. 普通运营不能通过修改前端字段绕过授权状态；
6. Provider Adapter 在真实上传前必须重新校验授权状态。

具体授权材料形式、保留期限、删除时限和法律文本仍为开放问题（见 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) 的 Q-007 / Q-008），不得擅自决定。本原则的正式决策记录为 [DECISION_LOG.md](DECISION_LOG.md) 的 D-011。

### 原则 7：Hifly-first，不是 Hifly-only

在飞影满足以下条件时，优先使用飞影完成数字人、声音、普通数字人口播、音频驱动、对口型、背景处理和相关视频能力：

- 功能覆盖满足产品需求
- 真实效果质量达标
- 自动化路径稳定
- 成本和生成时延可接受
- 能取得稳定 task ID、状态、结果和失败信息
- 可安全重试、对账和恢复
- 满足授权与敏感资产要求（原则 6 / D-011）

目的：减少运营配置、减少数字人和声音资产迁移、减少多供应商 Token 与账号管理、保持人物、声音和作品链路一致。

执行路径偏好：

```text
1. 飞影正式 API
2. 飞影 Playwright
3. 飞影人工接管的半自动流程
4. 其他 Provider
```

但这不是无条件强制：当其他 Provider 在关键功能、质量、稳定性、成本或合规上明显更优时，可以经相同 Provider Adapter 接入。**未经 capability 实际调研与验证，不得宣布飞影支持该能力。**

第一版普通运营界面**不要求用户选择 Provider**：用户选择的是生产结果类型，Provider Task Router 根据已验证能力路由；Provider 选择只进入高级设置、管理员配置或技术诊断区域。正式决策记录为 [DECISION_LOG.md](DECISION_LOG.md) 的 D-013。

### 原则 8：Cloud-first，Tencent Cloud first（企业内部平台）

第一版产品是可以通过浏览器访问的 Cloud-first Web Control Plane，默认部署目标为腾讯云（Tencent Cloud first，不是 Tencent Cloud only）。产品属于企业内部 AI 数字人内容生产平台，第一批服务企业内部的电商运营、内容生产、内容审核和管理团队，不是面向公众自助购买的通用消费者 SaaS。第一版先做单企业/单组织云端 MVP，但领域模型保留 Organization 边界。

- 业务领域模型不得依赖具体腾讯云产品名称；Database、ObjectStorage、Queue、SecretStore 使用基础设施抽象；腾讯云只作为第一版默认部署实现（具体服务待 Q-021）。
- **不建设支付、套餐、订阅、账单、充值、余额、优惠券、续费、面向客户的自动计费**；保留企业内部任务用量、Provider 消耗、LLM 调用量、成本估算、内部预算和限额、成员使用情况、审计日志、异常消耗告警（D-016）。
- 正式决策记录为 [DECISION_LOG.md](DECISION_LOG.md) 的 D-014 / D-015 / D-016。

### 原则 9：人物步骤「创建新人物或选择现有人物」

人物步骤统一表达为「创建新人物或选择现有人物」，产品入口至少规划：公共数字人、企业已有数字人、创建新人物。第一条端到端黄金路径与图片数字人创建拆开实施：Vertical Slice A（已有/公共人物黄金路径）用已有/公共人物打通端到端；Vertical Slice B（图片数字人创建）为独立子切片（上传人物图片 → 检查有效授权 → 创建飞影图片数字人异步任务 → 查询或接收任务状态 → 获取 Provider avatar 标识 → 登记 AvatarAsset → 回到统一人物选择流程 → 用于 VideoPlan）。创建人物必须遵守原则 6（D-011）。正式决策记录为 [DECISION_LOG.md](DECISION_LOG.md) 的 D-017。

### 原则 10：文案是 SaaS 自有能力，LLM 凭证两级模型

文案生成、版本管理、品牌规则、质检和审核属于 SaaS 自有业务能力，不得永久依赖飞影网页内置文案功能；架构采用 CopyGenerationService → LLM Provider Adapter（预留平台默认模型、企业自有 API Key、可替换 Provider、可配置 base URL 与 model）。普通运营用户只看到「生成文案」和业务配置。MVP 使用平台默认 LLM 凭证，普通用户零配置；MVP 平台默认 Provider 与默认模型已由 D-023 确定（DeepSeek 官方开放平台 / `deepseek-v4-flash`，显式非思考模式，JSON Output 与服务端校验）；后续企业 BYOK 是组织级配置，进入管理员高级设置；真实 Key 遵守 D-020 安全底线（不进入前端/仓库/Markdown/日志/错误信息/证据截图，页面只显示掩码，使用加密 Secret 引用）。正式决策记录为 [DECISION_LOG.md](DECISION_LOG.md) 的 D-019 / D-020 / D-023。

## 五、五阶段核心生产流程

这是产品最重要的主流程，定义为项目内部统一阶段导航：

```text
1. 商品与目标
2. 文案与质检
3. 人物与素材
4. 视频方案
5. 生成与交付
```

### 阶段一：商品与生产目标

用户创建的是「内容生产项目」，不是直接创建技术 batch。项目需要表达：

- 项目名称、品牌、目标平台、内容目标
- 商品数量、计划视频数量、每商品方案数量
- 视频形式、目标用户、内容风格
- 语言、期望时长、比例
- 品牌禁用词、品牌表达规则
- 交付日期、项目成员

**MVP 商品事实与文案门禁（D-021）**：商品可以先创建，**文案可以为空**。启用 AI 文案生成的最低商品输入：

- 必填：商品名称；至少一张商品图片；至少一条经用户确认的核心卖点；
- 可选：商品描述；已有文案。

商品图片主要服务后续数字人手持商品视频生产；图片识别不能自动创建正式商品事实；未经用户确认的信息不能进入 LLM 事实输入；AI 文案不得直接进入 VideoPlan。「文案为空」与「商品资料不满足生成条件」是两个不同状态。ContentBrief 的 MVP 规则已由 D-022 决定：**ContentBrief 不设置必填字段**，全部为可选输入，ContentBrief 为空或缺失不阻止文案生成（详见 D-022 与阶段二）。

示例：

```text
项目：8 月小红书防晒霜种草
目标平台：小红书
内容形式：数字人口播带货
商品数：10
每商品方案数：3
计划视频数：30
时长：20～35 秒
目标人群：20～30 岁通勤女性
风格：真实分享、轻种草
```

视频类型必须作为业务卡片呈现，而不是底层执行器名称：

- 手里有货
- 数字人口播
- 照片说话
- 对口型
- 实景口播
- 商品讲解
- 双人播客
- 自定义方案

第一版可以只真正执行少数类型，但产品模型必须允许后续扩展。

### 阶段二：文案生成与内容质检

文案生成、版本管理、品牌规则、质检和审核属于 **SaaS 自有业务能力**（D-019），不得永久依赖飞影网页内置文案功能；架构采用 CopyGenerationService → LLM Provider Adapter（见原则 10 与 [PROVIDER_AND_AGENT_ARCHITECTURE.md](PROVIDER_AND_AGENT_ARCHITECTURE.md)）。

文案有两个入口（D-021）：

```text
入口 A：结构化商品信息 + 内容目标 → AI 生成文案草稿
入口 B：已有文案 → 直接作为草稿，或 → AI 优化/改写 → 形成新草稿
```

两个入口最终都进入统一流程：

```text
CopyVariant → 质检 → 人工审核 → Approved CopyVariant → VideoPlan
```

**AI 文案事实约束（D-021）**：模型只能基于用户已确认的商品事实进行营销表达，不得自行编造功效、参数、成分、认证或奖项、销量、排名、价格、优惠、库存、活动期限、竞品对比结论、医疗或健康承诺及其他未经用户确认的事实性信息。所有 AI 生成文案均为草稿；AI 文案不得直接进入 VideoPlan，必须经过质检与人工确认后才能被 VideoPlan 引用。

**ContentBrief 可选输入与默认行为（D-022）**：生成文案的最低输入仍完全由 D-021 决定（商品名称、至少一张商品图片、至少一条经用户确认的核心卖点）；**ContentBrief 为可选，不设置任何必填字段**，不得成为第二套生成门禁。推荐流程：

```text
完成商品事实（D-021）
→ 可直接生成文案
或
→ 展开可选的内容偏好
→ 生成文案草稿
```

可选内容偏好（全部可选，无必填项）：

- **表达风格**：默认「自然口语化种草」；支持预设与用户自定义；除默认值外不固定完整预设目录；
- **种草角度**：默认由 AI 根据已确认商品名称、核心卖点、商品描述等事实选择；用户可指定或自定义；不得借种草角度补充未经确认的商品事实；
- **期望口播长度**：可选提示，只控制文案篇幅；**不等于成片时长**，不保证最终成片达到用户填写的秒数，不得展示精确时长保证；未填写时不阻止生成，也不固定默认秒数、默认字数或默认长度档位；
- **收尾方式**：产品界面统一使用「收尾方式」，不以 CTA 作为主要用户术语；默认「自然收尾」；可选「轻度引导」「无收尾引导」或用户自定义；
- **补充要求**：可选自由文本，用于描述特殊受众、发布渠道、表达限制、语言要求、禁用措辞或其他创作说明。

明确边界：

- 目标平台不作为 MVP 独立结构化字段；
- 目标人群不作为 MVP 独立结构化字段；
- MVP 不建设平台下拉列表、平台分类体系、人群标签体系或强制受众选择流程；特殊平台或受众要求写入补充要求；
- 补充要求与自定义收尾中的事实性内容（价格、优惠、库存、活动期限、试用装、赠品、销量、排名、功效、参数、认证、医疗或健康结论等）仍必须来自用户确认的商品事实，不能绕过 D-021 事实安全门禁；
- ContentBrief 为空或完全缺失时仍可生成文案，系统使用默认表达行为；
- 全部生成内容继续遵守 D-021（AI 文案为草稿，经质检与人工确认后才能进入 VideoPlan）。

**MVP 平台默认 LLM Provider（D-023）**：MVP 使用 DeepSeek 官方开放平台作为平台默认 LLM Provider，官方 API Key 由平台服务端管理，企业用户零配置。文案生成能力链路：

```text
D-021 Confirmed Product Facts
+ D-022 Optional ContentBrief
→ Platform CopyGenerationService
→ DeepSeek Official Provider Adapter
→ deepseek-v4-flash / non-thinking
→ JSON Output
→ Server Validation
→ CopyVariant Draft
→ Quality Gate
→ Human Approval
→ VideoPlan
```

明确边界（D-023）：

- 企业用户无需输入 LLM API Key；
- 不提供 Provider 选择器；
- 不提供模型选择器；
- 不提供 MVP BYOK（企业 BYOK 为后续版本能力，见 Q-020）；
- 不使用第三方中转或聚合平台；
- DeepSeek 输出不是最终文案（只是 CopyVariant 草稿）；
- 空内容、非法 JSON、截断或 Schema 不符的输出不保存；最多一次同模型受控重试，仍失败则任务失败、由用户手动重试；
- 不自动切换模型或 Provider；
- 商品图片不发送给 DeepSeek（生成请求只包含已确认文字事实、规范化 ContentBrief、系统指令与输出结构说明）；
- D-021 和 D-022 继续有效。

本 Decision 不代表 DeepSeek 已经接入、页面已经实现、服务已经部署、API 已经测试、V4-Pro 已启用或多 Provider fallback 已实现；也未获得 DeepSeek SLA 或合规保证。

每件商品不能只有一个 selling_points 和单条脚本，应建模为：

```text
商品
└── 内容方案
    ├── 内容角度
    ├── 开场钩子
    ├── 完整口播文案
    ├── 卖点覆盖
    ├── 行动引导
    ├── 预计时长
    ├── 目标平台
    ├── 质检结果
    ├── 版本
    └── 审核状态
```

内容角度至少支持：痛点切入、场景切入、对比测评、好物分享、成分解析、用户体验、限时促销、情绪价值、知识科普。一件商品可生成多个**真正不同**的内容角度，不是简单同义词改写。

文案工作流：

```text
CopyVariant 草稿
→ 确定性规则质检 + LLM 语义质检
→ invalid / blocked / needs_review / passed

invalid / blocked
→ 不可提交批准
→ 修复文案、补充并确认商品事实或修正规则输入
→ 创建新版本或产生新质检记录
→ 完整重新质检

needs_review
→ 提交人工审核
→ 审核人逐项查看 finding
→ 接受允许人工判断的提醒 / 要求修改 / 退回补充事实
→ approved 或 changes_requested

passed
→ 直接提交人工批准
→ approved 或 changes_requested

只有当前有效 approved
→ 才允许进入 VideoPlan
```

其中：`needs_review` 可以进入人工审核，审核人只能逐项处理 finding，不能「忽略全部」；一旦修改文案，必须创建新版本并完整重新质检；实际属于未确认事实的问题不能通过人工接受来放行；`passed ≠ approved`。

功能规划：生成多个版本、重新生成全文、只重写开头、只修改某一句、缩短或扩写、改成更口语化、改成指定平台风格、版本对比、固定当前版本、批量发起质检、批量提交 `passed` 文案审核、安全批量批准。

**MVP 文案质检与批准门禁（D-025）**：质检采用分层规则体系而非可抵消的百分比权重，权威顺序为 `已确认商品事实 → 平台强制规则 → 企业/品牌规则 → LLM 语义质检 → 人工业务确认`；平台强制规则不可被企业、品牌、LLM、人工或管理员覆盖。确定性规则引擎和 LLM 语义审查分别产生 finding；**Quality Result Aggregator 根据正式平台规则、企业/品牌规则、商品事实证据和品类规则映射 severity，并聚合决定最终质检状态**；LLM 只提出语义 finding 与 severity suggestion，不拥有直接放行权，不写入商品事实，也不能覆盖正式规则。自动质检结果为四类：

```text
invalid        质检过程或输入版本无效，未得到可信正式结果
blocked        存在不可绕过的事实/平台/法务/高风险规则失败
needs_review   存在可由审核人逐项判断的语义或质量 finding
passed         不存在阻断项，也不存在尚未处理的 review finding
```

关键边界（D-025）：

- **`passed ≠ approved`**：`passed` 是自动质检结果，`approved` 是人工批准结果；自动质检状态与人工审核状态分离；
- `invalid` 和 `blocked` **不能被人工或管理员直接覆盖**；硬阻断不能被其他维度得分抵消；不采用「事实安全低分 + 表达自然高分 = 平均后放行」；
- 人工审核状态为 `not_submitted` / `pending` / `approved` / `changes_requested` / `revoked`；`needs_review` finding 必须逐项记录接受理由，不能「忽略全部」；
- 质检结果不能只有通过/失败或一个总分，必须暴露**结构化 finding（命中片段、原因、证据、规则来源、修复建议）**；可以保留质量维度或辅助分数，但分数不是放行依据，也不能覆盖 hard block；
- 支持版本化**品类规则档案**（平台通用规则 + 企业/品牌规则 + 主要品类档案 + 已确认商品事实），品类只能加严、不能削弱平台门禁或事实门禁；未配置品类时使用通用规则；**品类不是文案生成的新必填条件**，MVP 不建设庞大固定的电商类目树，也不声明已拥有完整法律法规合规库；
- 文案正文、商品事实、核心卖点、ContentBrief、主要品类或任一规则版本变化后，**旧质检与旧批准失效，必须完整重新质检并重新审核**（不能只检查修改句子，不能沿用旧 approval）；
- 进入 VideoPlan 的最终门禁：CopyVariant 为当前有效版本、商品事实/ContentBrief/品类与规则版本仍有效、最新正式质检有效、不存在 `invalid` 或 `blocked`、`needs_review` finding 已逐项处理、存在当前有效 `approved`；任一条件失败拒绝进入或执行 VideoPlan。

本 Decision 不代表 CopyQualityService、规则引擎、LLM 语义审查或任何质检/审核 UI 已经实现；D-021（商品事实门禁）、D-022（ContentBrief 可选）继续有效。详见 [DECISION_LOG.md](DECISION_LOG.md) D-025。

### 阶段三：数字人、声音、背景与素材工作室

本阶段统一管理所有可复用生产资产。

人物步骤统一表达为「**创建新人物或选择现有人物**」（D-017）：

```text
人物与素材
├── 选择公共数字人
├── 选择企业已有人物
└── 创建新人物
```

选择已有/公共人物用于 Vertical Slice A 黄金路径；创建新人物（图片数字人）为 Vertical Slice B 独立子切片，须先有效授权并走异步任务登记 AvatarAsset。

**数字人资产**来源类型：公共数字人、用户上传照片创建、用户上传视频复刻、AI 生成人物、企业专属数字人、Provider 已有数字人引用。

数字人资产字段规划：名称、头像与预览、来源、Provider、Provider 内部引用、创建状态、授权状态、性别和年龄风格、适用品类、坐姿/站姿、正面/侧面/全身、可用视频类型、默认声音、标签、创建者、所属组织。**不得让普通用户看到本地文件路径作为主要信息。**

**声音资产**来源类型：公共音色、用户克隆声音、上传录音、文本转语音、Provider 音色引用。配置：语言、方言、性别风格、情绪、语速、音调、试听、授权状态、适用数字人。**数字人与声音不得永久硬绑定**，同一个数字人可以搭配多个声音。

**背景与场景资产**来源类型：纯色、家居、厨房、办公室、商场、户外、直播间、品牌定制、用户上传、AI 生成背景、原视频背景、Provider 模板。场景字段规划：横屏/竖屏、适用品类、画面亮度、背景复杂度、人物站位、商品展示区域、Logo 安全区域、推荐字幕位置、标签。

**其他素材**：商品图片、人物原图、原始视频、音频、Logo、字体、字幕模板、封面模板、品牌视觉规范、参考视频。

**对口型**应同时被定义为：一项 Provider 能力、一种视频生产模式、视频方案中的一个可配置步骤。输入：人物图片或视频、文案或音频、声音、背景、输出比例、字幕、是否保留原背景。输出：Provider 任务、对口型视频、质检结果、最终作品资产。

### 阶段四：视频方案与生成前审核

视频方案是内容与执行之间的**正式业务边界**。一个视频方案至少包含：

```text
商品、内容文案版本、视频类型、数字人、声音、背景/场景、
商品图片、人物图片或视频、字幕模板、封面模板、画面比例、
目标时长、Provider、生成参数、审核状态
```

示例卡片：

```text
防晒霜方案 01
文案：通勤防晒痛点版
人物：小雅·室内坐姿
视频形式：手里有货
比例：9:16
预计时长：27 秒
字幕：品牌简洁模板
场景：跟随人物素材或由 Provider 决定
状态：待审核
```

VideoPlan 保留通用的声音、背景/场景字段，但**字段是否展示和可用由当前视频类型的 Provider capability 决定**：capability 未验证支持的参数不得在 UI 中表达为可选。手里有货当前仅确认商品图与人物图输入，不提供独立声音、独立背景或场景选择（见 [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md) Q-017 与 [HIFLY_CAPABILITY_EVIDENCE.md](HIFLY_CAPABILITY_EVIDENCE.md)）。

运营人员操作：预览所有输入、更换人物、修改文案、复制方案、创建变体、批量应用配置、标记为已审核、退回上一阶段。**更换声音、更换背景或其他参数，仅在当前视频类型的 Provider capability 已验证支持时允许。**

审核流：

```text
草稿 → 待审核 → 需修改 → 已批准 → 已排入生产
```

发起生产前必须有 Preflight：商品素材是否完整、文案是否已确认、数字人是否可用、声音是否可用、授权是否完整、Provider 登录状态、Local Agent 在线状态、输出目录和磁盘状态、预计任务数、预计 Provider 消耗、风险提示、失败重试策略。

**内部 pointBudget 不得作为 SaaS 用户术语。** SaaS 用户看到的是任务数、预计用量、内部余量/预算和 Provider 成本提示（不建设面向客户的套餐/账单，见 D-016）。

### 阶段五：批量生产、质检、作品与交付

生产看板采用运营语言：待生成、生成素材中、素材待确认、视频生成中、下载中、已完成、需人工处理、已取消。

点击任务后再显示：当前阶段、执行日志、重试次数、Provider 任务 ID、本地执行器、失败原因、截图证据、产物、技术状态。

**现有底层状态机可以保留，但需要增加业务状态映射层。**

成片质检——第一阶段基础质检：文件存在、文件可播放、分辨率、比例、时长、音轨存在、黑屏检测、字幕存在、方案资产匹配、文案与音频时长匹配。后续 AI 质检：口型同步、人脸异常、商品变形、画面闪烁、字幕错误、敏感内容、Logo 遮挡、背景不一致。

作品库和交付——用户可以：预览作品、标记通过/退回、批量下载、按商品打包、下载文案、下载封面、下载审核表、导出项目交付包、标记已发布、记录发布平台和链接、记录表现数据。

Initial Owner/Admin bootstrap

## 七、MVP 与长期愿景

- **第一阶段（MVP 方向）**：第一版是 Cloud-first 的云端 Web 产品（默认部署腾讯云，单企业/单组织）；即使部分步骤仍需人工，也能完整走完五阶段产品链路；主导航克制（首页/项目/素材中心/生产任务/作品库/设置）；飞影多能力按优先级分批接入；本地执行内核继续承担真实执行；文案使用平台默认 LLM 凭证。详见 [DELIVERY_ROADMAP.md](DELIVERY_ROADMAP.md) 的 Phase 0～4。
- **长期愿景**：云端 SaaS Control Plane + 多 Local Agent + 多 Provider Adapter 的企业级数字人内容生产平台，含组织权限、企业治理与内部用量、企业 BYOK、模板市场、发布管理与数据复盘。
- MVP 与长期愿景之间不允许跳级：不一次性开发所有 SaaS 功能，不建设支付/套餐/账单系统（D-016）。
