# MVP 低保真页面结构与交互边界

> 状态：Accepted at product specification level
> Owner：owner（JettxonHo）
> 最后更新：2026-08-05
> 关联 Decision：[D-027](DECISION_LOG.md)
> 解决范围：Phase 1 全局信息架构、项目五阶段工作台、Vertical Slice A 完整页面流、状态/版本/失效/历史保留规则、业务界面与技术诊断边界、Phase 1 / Phase 2 验收分界
> 非目标：不实现功能、不固定品牌视觉/组件库/像素尺寸/前端框架/API 路径/数据库表，不解决 Q-018，不宣称 HIFLY-001 Evidence 已完成

本文件是 D-027 的详细 Specification。它只固化页面结构、交互边界与状态规则，**不代表任何页面、组件或 API 已经实现**。低保真不固定品牌视觉、组件库、像素尺寸、完整移动端布局、API 路径、数据库表、前端框架、精确长度/文件限制、密码数值策略、Provider 参数或 Hifly Token 保管位置。

---

## 1. 目的与适用范围

- 固定 Phase 1 的全局信息架构；
- 固定项目五阶段工作台；
- 固定 Vertical Slice A 的完整页面流；
- 定义各页面的主要区块、主操作、状态和异常；
- 明确自动检查（QC）与人工审核（Human Review）的区别；
- 明确版本、失效、撤销和历史保留规则；
- 明确业务界面与技术诊断界面之间的边界；
- 明确 Phase 1 与 Phase 2 的验收分界；
- 为后续拆分 Vertical Slice A 开发 Issue 提供产品依据。

## 2. Phase 1 / Phase 2 边界

- **Phase 1** 结束于可追踪的 `ProductionOrder` 和绑定该工单的人工交接包；
- **Phase 2** 才包含 Local Agent 真实领取、Provider 执行、状态与产物回传、服务端核验、正式作品登记；
- 普通界面使用业务语言；技术证据位于权限控制的次级诊断区。

## 3. 全局信息架构（LF-002 / LF-014）

桌面端全局结构：

```text
左侧一级导航
顶部上下文栏
页面标题及操作
主内容区域
可选右侧详情面板
```

一级导航只有 6 项：

1. 首页
2. 项目
3. 素材中心
4. 生产任务
5. 作品库
6. 设置

规则：

- 不展示组织切换、账单、充值或尚未实现的入口；
- 项目五阶段固定可见；后续阶段可浏览，但不满足门禁时禁止关键操作；
- 上游变化后下游显示「需要重新确认」；
- 每个页面只突出一个主操作；
- 长时间异步任务允许用户离开；
- 技术概念不进入普通业务主流程。

**不创建空页面**：模板中心、发布管理、数据分析、声音中心、背景与场景、模型配置、Provider 配置、套餐与账单均不在 Phase 1 一级入口。路由关系仅作为信息架构参考，不得在产品文档中错误声明为已实现 API 或前端框架约束。

关键对象应拥有稳定详情入口：商品、文案版本、VideoPlan 版本、ProductionOrder、Work、Asset、成员、Local Agent。

## 4. 项目五阶段工作台（LF-001）

```text
1. 商品与目标
2. 文案与质检
3. 人物与素材
4. 视频方案
5. 生成与交付
```

- 阶段顺序固定；不满足上游门禁时下游禁止关键操作；
- 异常必须返回数据权威页面（见 §18）。

## 5. Vertical Slice A（LF-001）

- 只创建空白项目；不提供模板选择；
- 人物只允许选择公共数字人或企业已有人物；创建新人物属于 Vertical Slice B；
- 声音、背景和场景不是 Vertical Slice A 的独立选择字段；
- Playwright、影刀、Provider 不作为普通运营用户的选择项；
- Local Agent 位于「设置」，并允许从阻断提示进入；
- Phase 1 结束于可追踪的 ProductionOrder 和绑定该工单的人工交接包；
- Local Agent 真实领取、执行和自动产物回传属于 Phase 2。

最终 Vertical Slice A 流程：

```text
工作邮箱登录
→ 首次登录修改临时密码
→ 创建空白项目
→ 添加商品
→ 填写并确认商品事实
→ 异步生成文案
→ 自动质检
→ 人工批准文案
→ 选择公共或企业已有人物
→ 创建 VideoPlan
→ 方案预检
→ 人工批准方案
→ 创建 ProductionOrder
→ Phase 1：waiting_for_executor；或生成绑定该工单的人工交接包
→ Phase 2：Local Agent 领取 → Provider 执行 → 状态与产物回传
→ 服务端产物核验
→ 创建 Work
→ 人工检查
→ 下载或创建 DeliveryRecord
```

## 6. 登录、首页与项目入口（LF-003）

**登录**：工作邮箱和密码；首次登录必须修改临时密码；登录后自动进入唯一企业；不提供公众注册、创建企业、短信登录、企业微信、SSO、邮件找回或组织选择（D-024）。

**首页**：是工作入口和待办中心，不是复杂数据分析墙；主操作是「创建项目」。

**项目列表**：桌面表格；不建设复杂标签和跨企业筛选。

**创建项目**：只创建空白项目；必填项目名称；描述和交付日期可选；**不在创建时选择模板、平台、受众、视频类型、Provider、人物、声音或背景**；创建后进入「商品与目标」空状态。

## 7. 商品与目标（LF-004）

三栏工作台：

- 左侧：项目商品列表；
- 中间：商品事实和内容偏好编辑；
- 右侧：文案生成准备度。

生成文案最低门禁（D-021）：商品名称；至少一张有效且经服务端核验的商品图片；至少一条非空、由用户确认的核心卖点。

规则：

- 不完整商品可以保存草稿；
- 内容偏好均为可选（D-022）；
- 卖点逐条记录并有独立确认状态；修改已确认卖点后该卖点重新变为未确认；
- 不提供「全部确认」、AI 自动确认或管理员绕过；
- 商品描述可选，不等同于已确认权威事实；
- 现有文案可作为输入，但仍需完整质检和人工审核；
- ContentBrief 默认折叠、可选，采用既有默认决策（D-022）；
- 右侧持续说明缺少的门禁；
- 支持自动保存和显式保存草稿；创建生成任务前必须存在稳定的已保存版本；
- 文案生成异步执行，用户可以离开；
- 不展示模型、DeepSeek、API Key、Prompt 或 Provider；
- 生成失败不产生有效文案；
- 相关上游变化会使旧质检失效、旧批准撤销，但保留历史。

## 8. 文案与质检（LF-005）

三栏工作台：

- 左侧：不可变文案版本列表；
- 中间：文案正文、编辑和版本对比；
- 右侧：自动质检和独立的人工审核。

界面术语统一使用：文案 / 文案版本 / 当前版本 / 历史版本（不在低保真文档中混用 `CopyVariant` 和 `CopyVersion`）。

文案版本展示：版本号、时间、来源、质检状态、人工审核状态和当前有效性。来源可包括 AI 生成、人工输入、AI 改写、人工编辑。已质检版本不能直接覆盖；修改正文必须创建新版本；历史版本只读；不删除已有审核或质检历史；可复制历史版本形成新版本，但必须完整重新质检。

自动质检状态：`invalid` / `blocked` / `needs_review` / `passed`。

人工审核状态：`not_submitted` / `pending` / `approved` / `changes_requested` / `revoked`。

核心规则（D-025）：

- **QC passed ≠ 文案 approved**；
- `invalid` 和 `blocked` 不允许人工绕过；`blocked` 不允许管理员覆盖；
- `needs_review` 必须逐项处理；接受提醒必须填写理由；未确认商品事实不能通过「接受提醒」绕过；
- `passed` 后仍需提交人工审核；只有当前有效、自动质检符合要求且人工 `approved` 的文案才能进入下一阶段。

质检 Finding 卡片应包含：标题、严重程度、命中文本、原因、规则或证据、修复建议，以及定位、人工修改、AI 改写、返回商品事实或查看证据操作。

禁止：忽略全部；接受全部；批量绕过 blocked；管理员强制批准；使用旧批准套用新版本。

AI 改写：用户可选择 Finding 和改写范围；使用业务指令，不提供 Prompt 编辑器；异步执行；生成新文案版本；完整重新质检；不覆盖旧版本；不继承旧质检和旧批准。

人工审核：审核人看到商品事实摘要、文案、质检结果、Finding、版本变化和历史；可批准或要求修改；要求修改必须填写意见；MVP 允许本人审核但必须明确记录 `self_review`；不强制双人审核。

批准后主操作：进入「人物与素材」。

以下相关变化触发重新质检或批准撤销：商品名称；商品图片；已确认核心卖点；参与生成和审核的关键商品描述事实；ContentBrief；品类；质检规则版本。**仅展示名称、排序或无关备注变化不应撤销批准。**

## 9. 人物与素材（LF-006）

Vertical Slice A 只用于选择：公共数字人、企业已有人物。

不提供：创建图片数字人；声音克隆；独立音色；独立背景；独立场景；Provider 选择；Playwright 或影刀配置；人物授权材料上传。

页面结构：左侧人物筛选和列表；中间人物预览与信息；右侧当前选择和可用性检查。

页面顶部显示：商品、当前 approved 文案版本、自动质检状态、人工审核状态、版本有效性。文案没有有效批准时可浏览人物，但不能确认人物并进入下一阶段，也不自动使用历史批准文案。

人物卡片显示：预览、名称、来源、业务可用状态、简短说明。业务状态示例：可用；暂不可用；需要执行环境；授权待确认；能力未验证。普通运营界面不显示 Provider avatar ID、Adapter、Cookie、Playwright、影刀或内部任务编号。

- 公共数字人：已由平台或企业准备；已有可追踪来源和使用范围；「公共」不等于互联网公开或所有企业共享；只展示已有能力证据支持的人物。
- 企业人物：显示授权有效、即将到期、已失效或信息不完整；授权无效时不能用于新方案；普通运营不能绕过授权。

只有有 Evidence 支撑的能力才可展示，不得因为人物存在就宣称支持任意声音、背景、商品、比例、时长或其他能力。

用户必须明确执行「确认人物选择」，不能因为列表第一项、最近使用或推荐而静默提交。

确认前检查：文案批准仍有效；人物存在；人物授权有效；人物兼容当前视频类型；必要资产可访问。

更换人物：不静默修改既有 VideoPlan；使现有 VideoPlan 需要重新确认；保留旧方案和批准历史。

**Local Agent 离线**：不影响浏览、选择人物和设计方案；只影响后续真实自动生产。

## 10. 视频方案（LF-007）

VideoPlan 组合：当前有效的 approved 文案；已确认人物；当前已有能力证据支持的配置。页面不执行真实视频生产，也不直接操作飞影、Playwright 或影刀。

主要区域：商品摘要、approved 文案摘要、已选人物摘要、当前视频配置、输出说明、方案预检、人工审核。商品、文案和人物是只读版本引用，修改必须返回各自所属阶段。

Vertical Slice A 只展示已经验证的配置。没有证据支持时，声音和场景由人物素材或执行能力决定，不提供独立配置入口。不展示：Provider 选择；飞影内部参数；Playwright；影刀；任意模型版本；未验证高级参数。

VideoPlan 为不可变版本，至少固定引用：商品版本、文案版本、人物资产版本、能力配置快照、创建人和时间、预检结果、审核状态。更换文案、人物、关键配置或影响生产的制作说明，必须创建新方案版本。

预检分为：A 上游有效性；B 方案完整性；C 生产准备度。

必须区分：

- **方案预检**：决定是否可以提交审核；
- **生产准备度**：决定已批准方案是否能够自动执行。

**Preflight passed ≠ VideoPlan approved。**

Local Agent 离线属于生产准备提醒：不阻止保存；不阻止方案预检；不阻止方案审核；不阻止创建 `waiting_for_executor` 的 ProductionOrder。

预检状态可包括：未运行；检查中；通过；存在提醒；被阻断；已失效。

方案预检与人工审核独立。人工审核状态：`not_submitted` / `pending` / `approved` / `changes_requested` / `revoked`。MVP 允许本人审核但记录 `self_review`。只有当前有效的 approved VideoPlan 才能创建 ProductionOrder。

上游变化后：旧预检失效；旧批准撤销；历史 VideoPlan 保留；已有 ProductionOrder 保留其原始方案快照；不静默重写历史工单。

## 11. 生成与交付（LF-008）

正式一致性口径：

```text
approved VideoPlan
→ 创建 ProductionOrder
→ 根据执行方式：等待 Local Agent；或生成绑定该 ProductionOrder 的结构化人工交接包
```

人工交接包不是绕过 ProductionOrder 的另一条业务记录；**人工交接包必须绑定 ProductionOrder**。

Phase 1：创建可追踪的 ProductionOrder；状态可为 `waiting_for_executor`；可生成绑定工单和 VideoPlan 版本的人工交接包；**不宣称已完成真实自动生产**。Phase 2：Local Agent 领取；Provider 执行；状态回传；产物回传；服务端核验；正式作品登记。

ProductionOrder 业务状态：`draft` / `ready` / `waiting_for_executor` / `claimed` / `running` / `requires_action` / `succeeded` / `failed` / `cancelled`。

普通界面必须明确区分：等待执行；执行环境已接收；生产中；需要人工处理；生产失败；生产完成；已取消。

工单、执行尝试和作品分别建模：`ProductionOrder └── ExecutionAttempt 1 └── ExecutionAttempt 2`。

重试规则：保留每次 attempt；只对可重试技术故障有限重试；不重复创建等价 ProductionOrder；不重复登记正式作品；不通过重试绕过失效 VideoPlan。

### 人工交接包与人工结果登记（D-029）

人工交接包的权威合同为 [MANUAL_HANDOFF_PACKAGE_CONTRACT.md](MANUAL_HANDOFF_PACKAGE_CONTRACT.md)（D-029）。生成与交付页面在 Phase 1 额外展示与反馈：

- 展示当前 `ManualHandoffPackage` 的 `package_id` 与 `package_version`，以及包状态 `generating` / `ready` / `generation_failed` / `superseded` / `expired` / `revoked`；
- 展示当前 manual `ExecutionAttempt`（`executor_type=manual`）及 `claimed/started/completed` 时间；
- 展示候选产物核验状态（候选产物 ≠ Work；上传完成 ≠ 核验通过）；
- **人工结果提交不能直接显示生产成功**：ManualExecutionReport `completed` 仅表示执行完成，ProductionOrder 是否 `succeeded` 由服务端候选产物核验 + Work 创建决定（ManualExecutionReport completed ≠ ProductionOrder succeeded；ExecutionAttempt succeeded ≠ ProductionOrder succeeded）；
- 交接包 `expired` 不代表本地副本已被远程清除（页面提示遵守企业清理/保留政策）；`revoked` 禁止开始新 manual attempt；`generation_failed` 提供脱敏错误与重试/返回 VideoPlan 入口。

边界（D-029）：生成/下载包 ≠ 开始执行；执行者领取并确认开始才创建 manual attempt；包与证据不得含 Secret/Cookie/密码/永久 URL/跨组织数据；回传时服务端重新校验组织/权限/版本/完整性，不只信前端隐藏字段。本节不增加高保真 UI、像素规格或未确认功能。

- **Local Agent 离线**：工单保持 `waiting_for_executor`；**不标记为失败**（`waiting_for_executor ≠ failed`）；可查看人工交接包。
- **`requires_action ≠ failed`**：`requires_action` 表示任务可经人工处理继续（例如登录态失效或页面验证）；「标记已处理」不能直接把任务改为成功，必须触发真实恢复或重新检查。
- **`ProductionOrder succeeded` 需要产物核验完成**：执行器报告完成后仍需核验对象存在、文件类型和大小、组织归属、工单追踪 ID，创建正式 Work，之后才标记生产完成。

返工：记录原因；返回相应上游阶段；创建新版本；重新审核；创建新 ProductionOrder；产生新 Work；保留原方案、工单、作品和新旧关系。

## 12. 全局生产任务（LF-009）

全局「生产任务」页面只管理：ProductionOrder、ExecutionAttempt、生产异常、产物回传和核验。

**文案生成、AI 改写、自动质检、素材上传核验等普通 AsyncJob 不进入生产任务主表**；它们在原页面持续显示状态，可通过轻量任务或待办入口返回，不和视频生产工单混合。ProductionOrder 只能从 approved VideoPlan 创建，不能在全局任务页脱离项目新建。

列表优先级：需要人工处理；失败；执行中；等待执行；已完成。列表字段：工单编号、项目、商品、VideoPlan 版本、当前状态、当前阶段、执行方式、更新时间、负责人、操作。默认不显示 Provider Task ID、Adapter、Playwright、影刀、lease、heartbeat、batch 路径或本地路径。

任务详情包含：业务摘要、生产时间线、当前处理事项、固定输入版本引用、产物与交付、权限控制的技术证据。

禁止：批量强制成功；批量跳过人工处理；批量覆盖失败原因；批量重置运行中任务；批量绕过失效方案。Phase 1 可采用定时轮询和手动刷新，不强制 WebSocket。

## 13. 作品库（LF-010）

统一术语：界面术语「作品」；领域对象 `Work`；交付事件 `DeliveryRecord`；**不将 Work 与 Deliverable 当作同义领域对象**（`Work ≠ DeliveryRecord`）。

作品库只接收：执行结果已回传；产物核验通过；来源版本完整；正式 Work 记录创建成功的作品。生产中的候选文件和核验失败记录继续留在生产任务中。

交付状态：待检查；可交付；需要返工；已交付。生产状态与交付状态独立。

作品固定引用生产时的：ProductionOrder、ExecutionAttempt、VideoPlan 版本、文案版本、人物资产、配置快照。

作品库支持：预览、人工检查、标记可交付、要求返工、安全下载、交付登记、历史来源查看。不建设：在线时间轴编辑、裁剪、字幕编辑、音轨替换、特效、自动发布、客户门户。

要求返工时：必须填写原因；原 Work 保持「需要返工」；返回上游创建新版本、新工单和新 Work；建立新旧作品关系；不直接替换旧作品文件。DeliveryRecord 可记录：交付时间、交付人、交付方式、交付备注。

Phase 1 不宣称 Local Agent 自动回传已打通。Phase 1 可通过受控的人工结果登记创建 Work，但必须绑定现有 ProductionOrder，**不允许上传无来源视频伪造成系统生产作品**。

## 14. 素材中心（LF-011）

素材中心是生产输入资产库，作品库是正式生产输出，两者分开。

Phase 1 支持：商品图片；普通业务素材；已有人物资产记录。不开放：创建图片数字人；声音克隆；独立音色资产；背景和场景编辑器；模板中心；在线视频编辑；Provider 素材同步；自动素材生成。

普通素材上传流程：获取短时上传授权 → 上传到对象存储 → 前端报告完成 → 服务端重新核验 → 创建或更新 Asset → 核验成功后才可用。普通上传入口不能处理：人物隐私源素材；声音克隆源文件；人物授权证明。

素材应通过版本化引用进入：商品、人物选择、VideoPlan、ProductionOrder 输入快照。文件内容、授权范围或生产相关信息变化时需要新 Asset 或资产版本。仅修改展示名称、普通标签等非生产元数据时，不应自动改变生产版本。

已被历史业务引用的素材：不能直接物理删除；可以停用（**停用 ≠ 删除**）；历史关系必须保留。人物敏感素材的删除期限继续由 Q-007、Q-008 等决策管理，不在 D-027 擅自固定。

## 15. 设置、成员与 Local Agent（LF-012）

Phase 1 设置区：企业信息；成员；Local Agent；系统信息。不提供：Provider 选择；AI 模型选择；API Key；BYOK；Hifly Token 输入；套餐和账单；充值；完整权限矩阵；完整审计中心。

企业信息：单企业；不展示组织切换、创建组织或跨组织迁移。

成员管理支持：成员列表；创建成员；查看首次登录或激活状态；重置临时密码；停用成员。创建成员：姓名、工作邮箱、基础角色、生成一次性显示的临时密码、首次登录强制修改密码（D-024）。停用成员不删除其项目、文案、审核、工单或作品历史。

粗粒度角色：管理员；运营；审核人；执行器管理员。这些角色只是粗粒度访问角色，**不代表已建设完整 RBAC**。

Local Agent 区分：

- 连接状态：在线；离线；连接中。
- 业务可用状态：可接收任务；正在执行；需要人工处理；配置不完整；版本不兼容。

**在线不等于业务可用。** 普通运营只看业务状态；执行器管理员可查看权限控制的脱敏诊断（Agent 版本、协议版本、最近心跳、ExecutionAttempt、登录态检查摘要、错误分类、脱敏证据）。**不得显示 Token、Cookie、账号密码、完整敏感路径或完整签名 URL。**

普通页面不能提供「使用 Playwright」或「使用影刀」的选择按钮；界面只表达：执行能力可用、不可用、需要管理员处理。**Q-018 仍开放**，因此不得设计 Hifly Token 前端输入和保存表单，也不得假设 Token 保管位置。

## 16. 全局反馈与异常（LF-013）

全局反馈分为：信息；提醒；阻断；失败。提醒不能弱化硬门禁。

阻断必须说明：为什么不能继续；受影响对象和版本；下一步操作；返回权威页面的入口。

保存状态统一：存在未保存修改；正在保存；已保存；保存失败。保存失败时保留用户本地输入，不清空表单，不静默丢失；创建异步任务前确认稳定保存版本。

异步任务：由服务端创建并持久追踪；用户可以离开页面；页面关闭不代表取消；不使用不可信的虚假百分比；不由前端自造成功状态。

所有禁用按钮必须解释原因。权限不足使用业务语言，不向普通用户暴露 403、RBAC 内部规则或技术堆栈。上游权威输入变化后使用：「需要重新确认」「批准已失效」「上游版本已变化」。不得静默删除或覆盖历史数据。

并发编辑：使用版本或乐观并发控制；后保存者不能静默覆盖先保存者；冲突时提供查看最新版本、复制当前内容或放弃修改。

必须区分：**删除**（只适用于无历史引用并符合删除规则的对象）/ **停用**（保留历史，禁止新引用）/ **撤销**（取消当前业务有效性，保留原决定）。高影响操作需要具体确认文案，说明对象和影响。

必须区分：真正空状态；筛选无结果；加载失败。普通界面显示业务错误；任务 ID、trace_id、ExecutionAttempt 和脱敏证据进入权限控制的技术诊断区。

## 17. 状态、版本、失效与历史保留

| 区分 | 含义 |
|---|---|
| QC passed ≠ 文案 approved | 自动质检通过仍需人工批准 |
| Preflight passed ≠ VideoPlan approved | 方案预检通过仍需人工批准方案 |
| ProductionOrder succeeded | 需要产物核验完成才标记 |
| Work ≠ DeliveryRecord | 作品与交付事件是不同领域对象 |
| waiting_for_executor ≠ failed | 等待执行不是失败 |
| requires_action ≠ failed | 需人工处理不是失败 |
| 停用 ≠ 删除 | 停用保留历史、禁止新引用 |
| 撤销 ≠ 删除 | 撤销取消当前有效性、保留原决定 |

版本与失效规则（LF-015）：只有参与生成、质检、审核或方案预检的相关权威输入快照变化，才触发失效；非生产展示元数据变化不应撤销批准。失效时旧质检 → superseded、旧批准 → revoked，历史记录与历史作品均保留，不静默覆盖。

## 19. 角色与技术诊断边界

- 普通运营界面使用业务语言；
- Provider avatar ID、Adapter、Cookie、Playwright、影刀、内部任务编号、lease、heartbeat、batch/本地路径、trace_id、ExecutionAttempt 等只在权限控制的技术诊断区展示；
- 管理员/运营/审核人/执行器管理员只是粗粒度访问角色，不代表已建设完整 RBAC；
- 待办入口是轻量入口，不是聊天或复杂消息中心；
- 人物能力只能展示已有 Evidence 支持的状态。

## 21. Phase 1 验收清单（页面覆盖）

每个列表页面至少覆盖：正常有数据；首次为空；筛选无结果；加载失败；权限不足。

每个编辑页面至少覆盖：初始草稿；未保存修改；保存中；已保存；保存失败；版本冲突；上游变化。

每个异步任务至少覆盖：等待；处理中；成功；需要人工处理；失败；已取消。

Phase 1 保留作品库入口和人工结果登记能力，但**不宣称自动执行和自动回传已经完成**。
