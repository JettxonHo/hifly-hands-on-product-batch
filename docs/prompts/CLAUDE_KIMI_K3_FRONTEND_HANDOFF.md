# Claude 对接 Kimi K3 前端升级提示词

以下提示词交给 Claude Code 使用。它授权 Claude 进行仓库调查、视觉阶段策划和 Kimi K3 对接准备；在 Owner 批准视觉方向前，不授权修改前端代码。

```text
你正在维护 GitHub 仓库：

https://github.com/JettxonHo/hifly-hands-on-product-batch

你的角色是 Stage 0 Claude Orchestrator。Kimi K3 是前端视觉设计 Agent，只负责视觉审计、设计系统、页面布局、响应式和动效方案。你负责读取仓库事实、控制边界、协调设计产出并复核业务合同。本轮不授权 Claude 或 Kimi K3 修改生产代码；Owner 批准 Stage 1 后，由 Codex 另行接手代码实现、测试和 Git 交付。

本轮目标：

依据仓库中的：

- AGENTS.md
- GOAL.md
- docs/status/CURRENT.md
- docs/agent-collaboration.md
- docs/frontend/KIMI_K3_FRONTEND_VISUAL_UPGRADE_PLAN.md
- docs/product/LOW_FIDELITY_PAGE_STRUCTURE.md
- docs/product/INFORMATION_ARCHITECTURE.md
- docs/product/VERTICAL_SLICE_A_DELIVERY_PLAN.md

完成 Kimi K3 前端视觉升级的 Stage 0：现状审计、视觉方向、页面样稿方案、实施边界和验收计划。完成后停止，等待 Owner 批准，不直接开始代码实现。

==================================================
一、运行时与角色真实性
==================================================

1. 必须实际调用 Kimi K3 执行视觉审计与方向设计。
2. 记录实际运行模型、会话和输出；无法验证时标记 UNVERIFIED_RUNTIME_MODEL。
3. Kimi K3 不可用时立即报告，不得静默改用其他模型并继续声称由 Kimi K3 完成。
4. Claude 不把模型输出直接视为产品决定，必须按仓库业务合同复核。
5. 不得把本提示词解释为 Claude 或 Kimi K3 的后续代码实施授权。

==================================================
二、本轮明确授权
==================================================

仅授权：

1. 读取仓库、GitHub Issues/PR 和最新 main 状态；
2. 检查当前工作区，创建独立只读调查上下文；
3. 向 Kimi K3 提供脱敏的页面结构、CSS、HTML 和本地截图；
4. 形成当前前端问题清单；
5. 形成视觉方向、设计 token、组件目录和动效规范草案；
6. 形成 A01-A03 桌面与窄屏方向稿或高保真静态原型；
7. 列出未来实施 Issue、依赖、文件范围、风险和验收场景；
8. 将最终策划结果写入本地独立设计文档；未经 Owner 另行授权，不创建 PR 草稿；
9. 输出 Owner 可快速审阅的视觉证据和决策清单。

本轮不授权：

- 修改 web/、src/、test/ 或业务代码；
- 改动 API、数据库、Migration、权限、Organization 隔离或状态机；
- 创建尚未实现的空页面并宣称功能完成；
- 修改 npm run gui、Playwright 或 Capture HTTP 行为；
- 新增前端框架、构建工具或大型依赖；
- 访问 Hifly、运行真实生成或消耗积分；
- 读取、保存或传递 Cookie、Token、密码、数据库凭据、浏览器 Profile；
- 提交 .local、config.local.json、素材、截图、视频、日志、HAR 或 node_modules；
- merge PR、关闭 Issue 或开始 VSA-A04 业务开发。

完成 Stage 0 后立即停止，等待 Owner 明确批准实施。

==================================================
三、产品与视觉方向
==================================================

这是企业内容生产运营工具，不是营销网站。目标是安静、专业、可扫描、适合重复操作的工作台。

必须遵守：

- 桌面优先，同时保证平板与窄屏不溢出；
- 完整目标 IA 的一级导航为：首页、项目、素材中心、生产任务、作品库、设置；Stage 0 可在静态方向稿中表达完整 IA，但后续代码只能显示已有真实功能的入口，不得创建或展示空路由、占位入口；
- 项目五阶段为：商品与目标、文案与质检、人物与素材、视频方案、生成与交付；
- 每页只突出一个主操作；
- 不使用营销 Hero、装饰性光球、大面积渐变或卡片套卡片；
- 卡片圆角不超过 8px；
- 不做单一紫蓝、深蓝或米色主导的一色界面；
- 运营页标题克制，不使用展示型超大字号；
- 熟悉操作使用图标，陌生图标有 tooltip；
- 状态、阻断、失效和下一步必须比装饰更突出；
- 动效只服务于保存、上传、异步任务、抽屉和状态变化；
- 不使用虚假进度、循环漂浮或大幅位移动画；
- 支持 prefers-reduced-motion；
- 长中文、长项目名、长 SKU、动态错误文案不得重叠或撑坏布局。

不得改变业务语义：

- QC passed 不等于文案 approved；
- Preflight passed 不等于 VideoPlan approved；
- waiting_for_executor 不等于 failed；
- requires_action 不等于 failed；
- Work 不等于 DeliveryRecord；
- 前端不能直接写服务端终态。

==================================================
四、Kimi K3 子任务
==================================================

请把以下任务原样或等价地交给 Kimi K3：

“审计当前 hifly-hands-on-product-batch 的 A01-A03 页面和共享样式，面向企业电商内容运营人员，提出一套安静、清晰、高效率的工作台视觉系统。请输出：

1. 当前视觉与交互问题，按影响排序；
2. 视觉原则、色彩、排版、间距、边框、阴影和密度；
3. 全局应用壳层与未来六项导航的静态 IA 方向；明确标记当前已实现入口，禁止把未实现入口做进代码；
4. 登录、项目列表、项目商品工作台、素材中心、成员管理的桌面与窄屏布局；
5. 按钮、表单、表格、状态标记、提示、空状态、对话框和异步任务组件；
6. 120-240ms 的克制动效规则及 reduced-motion 降级；
7. 需要保留的 DOM、可访问名称和业务状态；
8. 可按阶段实施的文件范围和验收截图清单。

不要修改业务流程，不增加未实现功能，不改 API/数据库/权限/状态机，不制作营销落地页，不使用卡片套卡片、装饰光球、单一紫蓝主题或夸张 Hero。先给设计方向和静态证据，未获 Owner 批准不得写代码。”

==================================================
五、Claude 必须完成的复核
==================================================

Claude 收到 Kimi K3 输出后必须检查：

1. 是否符合 D-027 的信息架构和状态边界；
2. 是否保留 A01-A03 已有功能和稳定 DOM/API 合同；
3. 是否出现尚未实现的导航、页面、按钮或成功状态；
4. 是否适合运营工具，而不是营销展示页；
5. 是否覆盖正常、空、加载、失败、禁用、权限不足、冲突和失效状态；
6. 是否覆盖桌面、平板、窄屏、键盘与 reduced-motion；
7. 是否避免新增框架或大型依赖；
8. 是否明确 Stage 1、Stage 2、Stage 3 的实施边界；
9. 是否遵守项目“真实核心风险优先、禁止过度防御、Rubric 不机械化”的工程原则。

==================================================
六、Stage 0 交付格式
==================================================

最终向 Owner 输出：

1. 当前页面问题摘要；
2. 推荐视觉方向及两种备选方向的主要取舍；
3. A01-A03 关键页面方向稿或截图；
4. 设计系统与动效摘要；
5. 明确不会改变的业务合同；
6. Stage 1 建议 Issue 标题、范围、文件和验收标准；
7. 需要 Owner 决定的事项；
8. 实际 Kimi K3 运行时证据；
9. 明确写出：本轮是否修改代码、是否访问 Hifly、是否消耗积分。

Stage 0 只能提出候选 Frontend Foundation Enabler。只有该能力确实跨多个 Slice 复用，且 Owner 单独建立并授权 Issue、任务合同、文件范围和回归范围后，才可实施；不得自行创建 Enabler、把整套视觉重构装进单一 PR，或搭车进入 A04。

Owner 未明确回复“批准 Stage 1 实施”前，不得开始代码实现。
```

Owner 批准 Stage 1 后，由 Codex 建立独立实施任务合同，明确 Issue、worktree、分支、允许修改文件、测试、截图视口、Review Agent 和禁止事项。不得把本策划提示词解释为 Claude 或 Kimi K3 的无限期开发授权。
