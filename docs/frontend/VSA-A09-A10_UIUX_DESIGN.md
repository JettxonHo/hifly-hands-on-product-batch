## 1. 用户工作流分析

### 1.1 进入原因与任务

| 角色 | 进入原因 | 要完成的任务 |
|---|---|---|
| 运营 | 视频方案已人工批准，要安排真实生产 | 选择业务目的 → 核对输入快照 → 创建生产工单 |
| 运营 | 同一方案需要返工重做 / 补充版本 / 再次生产 | 以明确目的创建新工单（旧工单与历史包保留） |
| 运营 | 工单已创建，要交给人工执行者 | 生成人工交接包 → 等待生成完成 → 下载交接包 → 线下转交执行者 |
| 运营 | 生成失败 / 下载授权过期 / 包被停用 | 查看原因 → 重试生成 / 重新获取下载授权 / 查看历史包 |
| 运营 | 日常巡检 | 扫多商品的「工单到哪一步」「包能否下载」 |
| 管理员 | 执行环境不可用 / 安全事件 | 看到 amber 提醒；停用（revoke）有问题的交接包（管理动作，UI 仅展示结果） |

主链路（单商品，本批终点加粗）：**视频方案已批准（A08）→ 创建生产工单（选择目的 + 摘要确认）→ 工单等待执行 → 生成交接包（异步，可离开）→ 包就绪 → 下载交接包（≠ 开始执行）→【A11 人工领取，本批禁用】**。

### 1.2 最高频动作（按优先级排序，决定布局与默认焦点）

1. 判断「这个商品现在能不能创建工单、为什么」。
2. 选择目的并创建工单（本批唯一门禁性创建动作）。
3. 判断「交接包生成好没有、能不能下载」。
4. 下载交接包。
5. 生成失败后的重试、下载授权过期后的重新获取。
6. 切换查看较早工单与历史包（低频；历史包折叠，工单仍按真实状态保留可用动作）。

### 1.3 最危险的误操作（按后果排序，决定确认层级与禁用策略）

1. **把「下载交接包」当成「开始执行」** —— 下载区固定提示「下载不代表开始执行」；包就绪 badge 与工单「等待执行」badge 永远并列；生成/下载均不创建 ExecutionAttempt（D-029 MHC-004、D-030 §10.2 反向测试）。
2. **重复点击创建出重复工单** —— 按钮受理即禁用；同一次创建意图复用同一幂等键，相同键 + 相同请求只产生一个等价工单；安全重放返回并打开该工单，显示「创建请求已受理，已为你打开对应工单」（Issue #65 幂等合同）。用户之后发起新的明确生产意图时使用新幂等键，即使方案与 purpose 相同也允许创建新工单（DM-004），不能把幂等误做成永久业务去重。
3. **把「等待执行」当成「失败」** —— `waiting_for_executor` 用信息蓝而非红；Local Agent 离线只显示 amber 提醒条「当前没有可用的执行环境，工单将等待人工执行；不影响创建工单与交接包」，不禁用任何创建/生成/下载按钮（Issue #65 验收场景、DM §24）。
4. **用已失效的批准创建工单** —— 创建前服务端重新验证 VideoPlanVersion + PlanReview；批准被撤销/预检已失效/上游已变化时创建按钮禁用，amber 阻断条说明原因并给「返回视频方案 →」链接，无绕过入口（Issue #65 验收场景）。
5. **把交接包当成可随意改内容的文件袋** —— 界面以业务摘要表达包内容（执行说明、输出要求、素材清单），明确「包内作业说明由系统从权威清单生成；如说明与清单不一致，此包视为异常，请勿继续生产并联系管理员」（D-029 §3），不提供任何手工编辑包内容的入口。
6. **以为过期/停用/被替代意味着本地副本被远程删除** —— `expired` / `revoked` / `superseded` 文案固定含「历史记录保留；已下载到本地的副本不会被远程删除，请按企业清理与保留政策处理」（D-029 §9、§18）。
7. **把生成失败当成终态** —— `generation_failed` 红色但提供脱敏原因 +【重新生成】（相同幂等请求安全重试）+「返回视频方案 →」入口（D-029 §20）。

### 1.4 本批与人工执行者的交接

- 交接物是 **下载后的 ZIP 交接包**（线下转交），系统内不建立执行者会话；执行者领取、开始执行、结果回传属 A11，本批只有禁用入口与说明。
- 页面必须让运营在下载前能说清三件事：这个包对应哪个工单与目的、包内有什么（业务摘要）、包的完整性如何核对（包版本 + 完整性摘要）。

## 2. 页面信息架构

### 2.1 结论：一个「生成与交付」工作台页面（项目阶段 5），不做两个页面

**评估**：候选方案 A 是「生产工单」与「交接包」两个稳定页面；候选方案 B 是一个阶段 5 工作台同时承载工单创建与交接包生成/下载。决定采用 **B**，理由：

1. **对象是同一条链**：交接包不是独立业务路径，必须绑定具体工单（D-029 §2、LF-008）；拆开会让「先看工单再跳另一页找它的包」成为高频跨页跳转，违反「异常与操作就近」原则。
2. **使用者与上下文相同**：都是同一运营、同一商品、同一 approved 方案上下文；A04-A08 已建立「左列表 / 中主对象 / 右门禁与决策」三栏心智，本页自然延伸为「左工单列表 / 中工单详情 / 右交接包」，运营零学习成本。
3. **状态判读需要同屏**：「工单等待执行 + 包可下载 + 下载≠执行」的区分依赖三类 badge 同屏并列；拆页会削弱 §1.3 的防误操作设计。
4. LF-008 将阶段 5「生成与交付」定义为一个阶段页面；LF-009 的全局「生产任务」页是跨项目视角且管理 ExecutionAttempt/异常/核验，属 A11+，本批不实现、不进导航。

**页面**：生成与交付（阶段 5，建议路由 `production.html`）。**导航**：一级导航维持现状（项目 / 素材中心 / 成员管理），不新增「生产任务」入口；阶段条第 5 阶段在 A09 落地后由纯文字升级为链接；A08 `plan.html` 批准后的禁用说明替换为「前往生成与交付 →」真实链接。

### 2.2 页面结构

```text
壳层（左侧导航 + 顶部上下文栏，现有 shell，不重设计）
└── 页面内容区
    ├── 页头：面包屑 + 阶段条（阶段 5 为当前阶段）
    ├── 商品上下文条：商品切换器 + 上游摘要（方案版本 · 已批准）
    ├── 门禁条（条件出现）：方案批准失效 / 无权限 / 执行环境提醒
    └── 三栏工作区
        ├── 左栏：工单列表（按创建时间排序 + 当前选中工单）
        ├── 中栏：工单详情（目的、状态、输入快照、创建信息）
        └── 右栏：交接包（当前包状态卡 + 生成/下载操作 + 历史包折叠区 + A11 禁用入口）
```

为什么这样布局：

- **工单列表在左**：同一方案可因明确业务目的重复生产并拥有多个工单（DM-004），列表按创建时间承载全部工单并支持选中切换，与方案版本列表的扫描方式同构。只有「选中」是界面状态；较早工单不会因此被标成 superseded、灰掉或失去其合法操作，所有记录永不静默消失（D-029 §19）。
- **工单详情在中**：目的、状态与固定输入快照是只读判读对象（工单创建后输入快照不变，D-029 §19），中栏无表单，避免「可编辑」错觉。
- **交接包在右**：生成/下载是门禁性与异步动作，固定在最右决策栏，与预检/审核位置一致；A11 禁用入口放在右栏底部，是用户视线终点，说明文字就地给出。
- **一个权威数据源**：所有状态从服务端读取；刷新/重进完整恢复；异步生成用轮询 + 手动刷新（LF-009 Phase 1 不强制 WebSocket）。

### 2.3 对象组织

| 对象 | 位置 | 组织方式 |
|---|---|---|
| 商品 | 上下文条切换器（与 copy/avatar/plan 同结构） | 下拉列表，每行：商品名（截断）+ 阶段状态摘要点 |
| 工单 | 左栏列表 | 双行行：目的中文名 + 创建时间一行，工单真实状态 badge + 包状态摘要点一行；选中行 tint-bg + 左 3px 品牌边。不得从创建先后推导领域状态 |
| 工单详情 | 中栏 | 目的卡（中文名 + 解释 + 固定快照说明）→ 状态区 → 输入快照四张只读卡（商品快照 / 文案 / 人物 / 方案，各带「查看 →」返回权威阶段）→ 创建信息（创建人/时间） |
| 交接包 | 右栏 | 当前包状态卡（状态 badge + 包版本 + 创建时间 + 完整性摘要）→ 操作区（生成/下载/重试/重新获取授权）→ 内容业务摘要（折叠）→ 历史包折叠区 → A11 禁用入口 |
| 执行环境 | 右栏顶部提醒条（条件出现） | amber 提醒，非红、非阻断 |

### 3.4 页级主操作唯一化规则（每屏仅一枚实心品牌色按钮）

| 页面 / 当前上下文 | 主操作【主】 | 同屏次操作 |

### 3.5 主要交互优先级

1. 状态判读（工单状态 + 包状态 + 执行环境提醒）永远同屏可见，不需滚动；
2. 当前下一步动作（主操作）在视口内且位置稳定；
3. 阻断/失效原因就地展示并带「返回权威阶段 →」链接，不跳页核对；
4. 低频对象中，历史包、包内容摘要与创建信息进入折叠区；较早工单保持可扫描列表行，只用选中态区分，不用灰色暗示失效。

## 5. 状态设计

颜色语义严格映射 `tokens.css`：成功绿（success）、提醒 amber（warning）、失败红（danger）、失效灰（inactive = N 系纯灰）、进行中信息蓝（progress）。红只给真实失败与危险确认，绝不给等待/待处理/阻断/离线提醒（Stage 0 §5.4 红线）。

### 5.1 ProductionOrder 生命周期（领域持久状态，DM §15；本批只投影前三个）

| 状态 | 中文文案 | 颜色语义 | 下一步操作 |
|---|---|---|---|
| `draft` | 草稿（输入尚未固定） | 中性灰 | 过渡态；若服务端返回则显示「正在固定输入快照」，不提供编辑入口（本批创建即固定快照） |
| `ready` | 已就绪 | 信息蓝 | 过渡态；随即转入等待执行；文案「工单已创建，正在转入等待执行」 |
| `waiting_for_executor` | 等待执行 | 信息蓝 | 生成/下载交接包；**明确不是失败**；等待人工领取（A11 入口禁用说明） |

`claimed` / `running` / `requires_action` / `succeeded` / `failed` / `cancel_requested` / `cancelled` 不在本批出现；若服务端异常返回未知状态，界面显示中性灰「状态待确认」+ 手动刷新，不错误归类为失败或成功。

### 5.2 工单创建门禁与异常（服务端计算，界面逐条投影）

| 状态 | 中文文案 | 呈现 | 下一步 |
|---|---|---|---|
| `business_blocked`（方案未批准） | 「视频方案尚未通过人工审核，不能创建工单」 | amber blocked notice + 创建按钮禁用 | 「返回视频方案 →」完成审核 |
| `business_blocked`（批准已撤销/预检已失效/上游已变化） | 「方案批准已失效：<变化类别>，不能创建工单」 | amber blocked notice + 创建按钮禁用；已有工单仍按各自固定快照与真实状态展示 | 返回视频方案创建新版本 + 重新预检 + 重新审核；已有工单动作由其自身门禁决定 |
| `business_blocked`（输入引用不完整） | 「方案引用的商品/文案/人物信息不完整」 | amber blocked notice + 逐条缺失项 | 返回对应权威阶段处理 |
| `technical_failure`（创建命令失败） | 「创建未完成（技术原因），你的操作未生效」 | 红色 error notice + [重试] | 重试（相同幂等键安全重放） |
| `no_permission` | 「你可以查看，但没有创建工单/生成交接包权限」 | amber blocked notice + 相关按钮禁用并附原因 | 「请联系管理员或有权限的成员处理」 |
| 幂等安全重放（同一 key + 同一 payload） | 「创建请求已受理，已为你打开对应工单」 | 信息蓝 notice + 自动定位到首次结果 | 在首次结果上继续，不创建重复工单 |
| `version_conflict`（同一 key + 不同 payload，或其他乐观并发冲突） | 「创建信息已变化，请刷新后重新确认」 | amber notice，不自动猜测用户目的 | 刷新权威状态，重新打开创建 Dialog 并产生新的明确请求 |
| 跨组织/非法 ID | 「此对象不在本企业可用范围内」 | amber blocked notice（服务端拒绝后的业务文案，不显示 403/错误码/内部 ID） | 返回项目内权威页面 |

### 5.3 执行环境提醒（Local Agent 离线的界面投影，非工单状态）

| 投影 | 中文文案 | 颜色语义 | 下一步操作 |
|---|---|---|---|
| 无可用执行环境 | 「当前没有可用的执行环境，工单将等待人工执行；不影响创建工单与交接包」 | 提醒 amber（页面级提醒条，非红、非弹窗） | 无需操作；管理员可前往「设置」处理执行环境；创建/生成/下载全部可用 |

### 5.4 execution purpose（创建时固定业务快照，D-029 §6、DM-004）

| 枚举 | 中文名 | 界面解释（创建 Dialog 与目的卡共用） |
|---|---|---|
| `first_production` | 首次生产 | 本商品首次安排真实生产。 |
| `rework` | 返工重做 | 此前生产结果不满足要求，按相同方案重新生产。 |
| `supplemental_version` | 补充版本 | 在已有生产结果之外，按相同方案追加生产一个版本。 |
| `reproduction` | 再次生产 | 按相同方案再次生产（例如原产物不可用或需要重出）。 |

规则：目的是工单创建时的固定快照，创建后不可修改；同一次点击链路重放不得自动产生新目的或新工单；同一方案可因明确业务目的重复生产，每次新的明确创建意图使用新幂等键并产生新 ProductionOrder，全部工单保留。

### 5.5 ManualHandoffPackage 生命周期（领域持久状态，D-029 §9）

| 状态 | 中文文案 | 颜色语义 | 下一步操作 |
|---|---|---|---|
| `generating` | 生成中 | 信息蓝 +「生成需要时间，可离开本页，回来后状态自动更新」 | 等待；轮询恢复；无百分比、无假进度 |
| `ready` | 可下载 | 成功绿 | 【下载交接包】；badge 旁常显工单「等待执行」状态，明示「下载 ≠ 开始执行」 |
| `generation_failed` | 生成失败 | 失败红 + 脱敏原因 | 【重新生成交接包】（相同幂等请求安全重试）；必要时「返回视频方案 →」；工单不进入任何执行状态 |
| `superseded` | 已被新版本替代 | 失效灰 | 历史包折叠区只读保留；说明「已被交接包 v(N+1) 替代」；历史引用不改写 |
| `expired` | 下载授权已过期 | 提醒 amber | 【重新获取下载授权】；内容未变化时不创建新包版本；文案固定含「历史记录保留；已下载的本地副本不会被远程删除」 |
| `revoked` | 已停用 | 失效灰 + 停用原因（业务文案） | 不可下载、不可用于开始执行；文案固定含「已下载的本地副本不会被远程删除，请按企业清理与保留政策处理」 |

### 5.6 包内容与完整性的用户可理解投影（D-029 §5、§7）

右栏「包内容摘要」折叠区只展示业务语言：

| manifest 概念 | 界面投影 |
|---|---|
| `package_id` / `package_version` | 「交接包 v1」+「包编号」（短格式，D-029 要求可核对，见 §10.2 D2） |
| `manifest_hash` / `package_hash` | 「完整性摘要：XXXX-XXXX」（短摘要 + 「用于核对包内容未被改动」，不出现 hash 算法名） |
| `contract_type` / `contract_version` | 不展示（内部合同版本，普通用户无决策意义） |
| `execution_steps` / `business_constraints` / `human_confirmation_points` | 「作业说明要点」逐条业务文案（与包内 README 同源的派生摘要） |
| `primary_output` / `file_naming_rule` / `accepted_media_types` / `expected_quantity` | 「输出要求」：主要产物数量、文件命名规则、接受的文件类型（中文媒体类型描述） |
| 素材 `retrieval_mode = embedded` | 「已随包附带」 |
| 素材 `retrieval_mode = short_lived_fetch` | 「使用时经系统短时授权下载；授权过期可重新获取，不影响包内容」 |
| 素材 `retrieval_mode = provider_existing` | 「已在执行环境中，按包内说明人工确认」 |
| 禁止内容（Secret/Cookie/Profile/永久 URL） | 不展示任何此类字段；界面静态承诺文案「交接包不包含账号密码、登录凭据或长期有效链接」 |

### 5.7 页面级状态（本页通用）

| 状态 | 中文文案 | 呈现 | 下一步 |
|---|---|---|---|
| 加载中 | — | 列表与卡片骨架行 | 不显示「正在加载…」兜底文案 |
| 空状态 | 工单：「还没有生产工单」+【创建生产工单】引导；包：「尚无交接包」说明 | 三分类：真空 / 门禁阻断 / 加载失败（error notice + [重试]） | 见 §3.2 |
| 异步恢复 | 生成中离开再回来 | 状态全部由服务端重建；轮询 + 手动刷新 | 无假进度条 |
| 无权限 | 见 §5.2 | amber + 按钮禁用带原因 | 联系管理员 |
| 下载授权过期（点击下载时） | 「下载授权已过期，请重新获取」 | amber notice + 自动出现【重新获取下载授权】 | 重新获取后下载；不创建新包版本 |

### 5.8 必须保持的关键区分（设计与文案双重保证）

1. **方案已批准 ≠ 工单已创建**：批准只解锁「创建工单」入口；工单永远由用户显式选择目的后创建，无自动创建。
2. **waiting_for_executor ≠ failed**：等待执行为信息蓝正常状态；红只给真实技术失败；Local Agent 离线仅 amber 提醒且不阻断任何本批操作（Issue #65 验收场景）。
3. **package ready / 已下载 ≠ execution started**：包就绪 badge 与工单「等待执行」badge 同屏并列；下载按钮旁固定提示「下载不代表开始执行」；生成与下载均不创建 ExecutionAttempt（D-029 MHC-004）。
4. **manifest 权威 / README 派生**：界面只给业务摘要并静态说明「包内作业说明由系统从权威清单派生；两者不一致时此包视为异常，请勿继续生产并联系管理员」（D-029 §3）；不提供编辑包内容入口。
5. **expired / revoked / superseded ≠ 本地副本已删除**：三者文案固定含「历史记录保留；本地副本不会被远程删除」（D-029 §9、§18）。
6. **purpose 固定快照**：创建后目的不可改；同一幂等请求重放只回到首次工单；新的明确生产意图（可与已有 purpose 相同）使用新请求创建新工单。
7. **UI 投影标注**：「已就绪」「正在转入等待执行」「状态待确认」为投影文案；本设计未发明任何新领域状态，全部映射 D-028 §15 与 D-029 §9。

## 7. 交互设计

### 7.1 创建工单（A09 唯一门禁性创建动作）

- **入口**：无工单时中栏空态【创建生产工单】与左栏【+ 创建工单】；已有工单时左栏【+ 创建工单】（用于返工/补充/再次生产）。
- **门禁**：按钮可见性不要求门禁通过，但门禁不满足时禁用并在上方 amber 逐条列出原因 +「返回视频方案 →」；打开 Dialog 时与服务端命令执行时均由服务端重新验证（当前有效 approved VideoPlanVersion + PlanReview + 预检未失效 + 引用完整 + 权限 + Organization）。
- **Dialog 结构**（一次摘要确认，不叠加二次确认）：
  1. 目的单选（四项，中文名 + 一句解释，默认不预选，未选择时确认按钮禁用——目的是业务决定，不替用户默认）；
  2. 输入快照摘要（方案版本 / 文案版本 / 人物 / 商品快照，只读）；
  3. 静态说明「工单创建后目的与输入快照固定，不可修改；同一次创建请求重复提交不会生成重复工单」；
  4. 确认按钮「确认创建工单」（实心主色）。
- **幂等与防重复**：按钮受理即禁用（受理态）；同一次点击/双击/网络重试复用同一幂等键，相同 key + 相同 payload 返回首次工单，页面定位并显示信息蓝 notice「创建请求已受理，已为你打开对应工单」。用户关闭 Dialog 后再次显式发起生产属于新业务命令，使用新 key；不能因方案版本与 purpose 相同而自动返回旧工单。
- **成功后**：工单行插入左栏顶部并选中；中栏展示详情；状态投影「已就绪，正在转入等待执行」→ 轮询后「等待执行」；右栏出现【生成交接包】主操作。
- **并发**：创建携带幂等键（沿用 projects 页 idempotency-key 先例）；只有同 key + 同 payload 才安全回放。相同 key + 不同 payload 或权威输入已变化时显示 409 恢复流程，刷新后由用户重新确认；不能把他人独立创建或新的生产意图误判为重复提交。

### 7.2 生成交接包（A10）

- **运行**：【生成交接包】→ 按钮 loading 受理即禁用 → 「生成中」信息蓝 +「可离开本页」说明；轮询恢复；无百分比、无假进度。
- **幂等**：同一工单重复触发返回同一包或同一生成任务（`production_order_id + package_version + contract_version + generation_request_id`，D-029 §17）；已有进行中生成时入口禁用显示「已有生成任务进行中」。
- **离开/刷新恢复**：生成中离开页面、刷新、重进，状态由服务端重建为「生成中 / 可下载 / 生成失败」之一；不产生幽灵任务。
- **失败**：红色「生成失败」+ 脱敏原因（业务语言，不出现堆栈/内部路径/对象存储细节）+【重新生成交接包】+「返回视频方案 →」；重试使用相同幂等请求；工单保持「等待执行」，不进入任何执行状态（D-029 §20）。
- **重新生成语义**：修正说明/命名规则等产生新 `package_version`，旧包 `superseded` 进历史折叠区；生产输入或目的变化不允许通过重新生成偷换输入——界面无此入口，服务端亦拒绝（D-029 §4、§10）。

### 7.3 下载交接包（A10）

- **下载**：【下载交接包】→ 浏览器下载；按钮旁固定提示「下载不代表开始执行」；下载完成后 success notice「交接包已开始下载。请妥善保管本地副本，按企业清理与保留政策处理」。
- **不创建任何执行记录**：生成与下载均不创建 ExecutionAttempt（D-030 §10.2 反向测试）；界面不出现「已开始执行」类文案。
- **重复下载**：允许；同一用户重复下载不创建新业务版本（D-029 §10）。
- **授权过期**：下载授权过期时 amber「下载授权已过期」+【重新获取下载授权】；重新签发不改变包内容、不创建新包版本；expired 历史保留且不暗示本地副本被删除。
- **已停用（revoked）**：下载按钮禁用 + 失效灰 badge + 停用原因（业务文案）+ 保留政策提示；历史包仍可查看摘要，不提供下载。

### 7.4 历史查看

- 工单列表：所有工单保留并按服务端真实状态展示。点击较早工单仍可查看其只读输入快照、创建信息与包历史；若该工单仍满足 A10 动作门禁，右栏照常提供生成、重试或下载，不能仅因创建较早而隐藏操作。终态或禁止动作的解释由服务端投影，本批不虚构工单 superseded 状态。
- 历史包：右栏折叠区，每行「交接包 vN · 状态 badge · 创建时间」；superseded 行注明「已被 v(N+1) 替代」；expired/revoked 行带保留政策提示；全部只读，不删除、不覆盖。

### 7.5 危险操作与 Dialog 使用（低打扰原则）

| 操作 | 是否 Dialog | 理由 |
|---|---|---|
| 创建工单 | 是（目的选择 + 摘要确认） | 门禁性创建动作，目的是业务决定，一次摘要确认防误触 |
| 生成交接包 | 否 | 可安全重试、幂等，按钮受理态即反馈 |
| 重新生成交接包 | 否 | 同上；旧包自动进历史，无数据丢失 |
| 下载交接包 | 否 | 可逆、可重复；保留政策提示用就地文案，不用模态打断 |
| 重新获取下载授权 | 否 | 纯授权续期 |
| 切换工单/商品 | 否 | 本页无本地未保存输入，无需离开保护 |

### 7.6 终态边界

前端只发业务命令（创建工单/生成交接包/重新生成/下载/重新获取授权），**永不直接写 `ready` / `waiting_for_executor` / 包 `ready` 等终态**；所有 badge 来自服务端响应；异步进行中只有「等待」投影，不做乐观完成。

## 8. 动效设计

全部使用既有 token：`--motion-fast: 140ms`、`--motion-panel: 220ms`、`--ease-out: cubic-bezier(0.2, 0, 0.38, 1)`。时长区间 120–240ms，ease-out，无弹簧/回弹/循环。

| 场景 | 动效 | 时长 |
|---|---|---|
| 创建成功 / 下载反馈 / 状态 notice 出现 | opacity 淡入（既有 `notice-in`） | 150ms |
| 状态 badge 变化（已就绪→等待执行；生成中→可下载/生成失败） | 颜色 cross-fade | 120ms |
| 工单列表插入新工单 / 历史包列表插入 | 单次淡入，无位移弹跳 | 140ms |
| 创建 Dialog / 移动端工单抽屉 | opacity + translateY(8px→0)（既有 `dialog-in`） | 200–220ms |
| 选中工单行 / 折叠区展开 | 背景色、边框色过渡 | 120–150ms |
| 列表骨架（加载中） | 静态灰条或单次淡入 | — |

明确禁止：虚假进度条（生成中只显示状态 badge 与说明，不显示百分比）；循环呼吸/脉冲 spinner 以外的等待暗示之外任何循环动画；数字滚动；位移动画引起的布局跳动；任何 > 240ms 的动效；把等待动画当作成功证据。

**prefers-reduced-motion**：沿用 base.css 既有 media query（全部 transition/animation 压至 0.01ms）；本页补充——抽屉/对话框瞬时显隐、生成中以静态「生成中」badge + 文案表达、骨架不闪烁；状态信息永不依赖动效传达（badge 颜色 + 文字双编码）。
