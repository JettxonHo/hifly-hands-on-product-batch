## 1. 目的与证据边界

本审计从飞影企业内容运营的真实任务、频率、错误代价、权限与生产门禁出发，检查当前企业入口、项目、内容生产、
生产执行、作品、素材和成员管理是否形成连续、可理解、可恢复的运营工作台。它回答“当前哪里有问题、为什么有问题、
后续设计必须解决什么”，不直接给视觉方案，也不把外部工作台当作本项目的信息架构来源。

证据来自以下三类，结论不跨证据类型外推：

- 当前 `main` 的页面、前端逻辑、产品 IA、用户流程和已批准的运营任务流合同；
- 11 条使用内存仓储、假数据和本地 Chromium 的既有公开浏览器 seam，验证页面行为与恢复路径；
- Login、Projects、Project、Copy、Avatar、Plan 的既有三视口截图，以及在同一全功能 runtime、同一管理员角色下补录的
  Production、Works、Assets、Members 三视口截图；
- 同一管理员在 Projects、Project、Copy、Avatar、Plan、Production、Works、Assets、Members 的可见一级导航对照，
  九页均为“项目 / 素材中心 / 作品库 / 成员管理”；
- 加载、空态、错误、权限、dirty、保存、冲突、历史版本、异步状态和终态恢复的已有公开回归。

本轮未访问飞影、未调用 Provider、未启动 Worker、未写生产数据、未生成视频、未消耗积分。临时截图位于
`/private/tmp/hifly-ux-audit-screens/` 与 `/private/tmp/hifly-ux-audit-same-context/`，仅作审计证据，不进入 Git。
显式 legacy `/index.html` 本轮仅使用源码、DOM 合同和已有公开 seam 审计，没有补录截图。

## 2. 角色、任务、频率与错误代价

| 角色 | 高频任务 | 频率 | 主要错误代价 | 界面应优先回答 |
|---|---|---:|---|---|
| 内容运营 | 找到当前项目和商品，补资料，生成并修订文案，选择人物和方案 | 每日、高频 | 改错商品、覆盖未保存内容、错误上游继续流转 | 当前对象、阶段、阻断和唯一下一步 |
| 内容审核人 | 区分自动质检与人工审核，批准、驳回或要求修改 | 每日、多次检查点 | 把 QC passed 当成人工批准，导致错误内容进入生产 | 审核对象版本、依据、状态差异和影响范围 |
| 生产运营 | 创建当前唯一工单，观察执行，处理异常，核验与交付 | 每批次、高错误成本 | 重复出片、积分浪费、错误作品交付、失败后继续跑下一条 | 当前商品是否可执行、是否运行、需谁处理、是否完成 |
| 组织管理员 | 管理成员、权限和企业人物目录 | 低频、影响面大 | 错授权限、停用错误成员、临时密码泄露 | 操作对象、权限影响、危险动作确认与审计结果 |
| 技术/执行管理员 | 诊断 Cloud Executor、attempt、交接包和远端执行 | 低频、专业 | 把基础设施异常误判成业务失败，或绕过 fail-closed 门禁 | 技术证据可展开，但不能取代业务状态主叙事 |

结论：主要导航与页面首屏应围绕“项目中的商品如何走到可交付作品”组织。管理员和技术诊断是必要能力，但不应占据
普通运营的默认阅读路径。

## 3. 严重度与根因分类

- **P0**：可能造成权限越界、生产安全门禁失效、真实积分重复消耗或主要流程不可完成。
- **P1**：高频任务容易误判、误操作或失去上下文，显著提高培训与恢复成本。
- **P2**：不阻断任务，但降低扫描效率、一致性、中文可理解性或响应式质量。

本轮本地假数据审计未发现新的 P0。该结论不代表真实 Provider、生产部署或长期运行不存在 P0，只说明当前公开 UI seam
未显示新的生产安全失效。P1 必须先进入后续设计合同，P2 可随对应切片做 targeted upgrade。

根因类别使用：`IA`、`操作层级`、`控件语义`、`中文内容`、`状态/错误`、`权限/审计`、`响应式/无障碍`。

## 5. 跨页问题聚类

### 5.1 信息架构

- 同一 runtime/角色下一级导航跨页一致；未解决的是一级导航与项目阶段导航的职责边界，以及缺少全局生产任务入口。
- 页面组织仍部分沿用技术模块（Copy、Plan、Cloud Executor、Asset），没有完全围绕“项目中的商品生产任务”组织。
- 管理员目录、普通运营选择和技术诊断虽已在部分页面分层，但全局入口仍没有一致规则。

### 5.2 操作层级

- Slice A/B 已建立“唯一推荐下一步”，但页头刷新、模块级动作和终态动作仍会形成多个同等强调按钮。
- Production 与 Works 的问题最严重：前者技术区抢占主叙事，后者终态仍出现检查和重复交付动作。
- 危险或成本动作必须继续由服务端状态、人工确认和 fail-closed 门禁约束，不能以视觉简化替代安全合同。

### 5.3 控件语义

- 导航链接、阶段链接、刷新按钮和上下文动作的作用域不总是清楚。
- 筛选存在于 Avatar/Works，但 Projects/Assets 缺乏与规模匹配的定位能力；是否新增搜索或安全批量动作要以任务频率和 API 真值为准。
- Dialog 已用于创建与危险确认，方向正确；后续不能把选择器、Tab 或 Dialog 仅作为视觉容器互换。

### 5.4 中文内容

- 内部对象名和英文状态广泛暴露，造成“业务步骤”和“技术实现”混读。
- “存在提醒”“需进入核对”“刷新重试”等文案缺少责任人、后果或恢复条件。
- 状态名称必须统一，但不能把 QC passed、preflight passed、生成成功改写为人工批准。

### 5.5 状态与错误

- Slice A/B 的 dirty、冲突、历史、异步失败恢复较完整，是后续页面的基线。
- Assets/Members 仍可能同时显示 loading 与 error；Production/Works 终态主操作未完全收敛。
- 页面需要区分业务阻断、权限不足、技术失败、处理中、已完成，不用同一个 notice 或“重试”覆盖所有情况。

### 5.6 权限与审计

- 组织隔离、admin-only 成员入口、深链安全 fallback 和服务端授权合同必须保留。
- 审计历史、attempt、hash、内部 ID 不能删除，但普通运营默认只需看到业务结果；技术详情应渐进披露。
- 非 admin 回落继续进入企业 Projects，不能退回 legacy 工作台。

### 5.7 响应式与可访问性

- 现有公开回归和本轮补录已覆盖 Login 至 Members 的 1440/768/390 页面证据，并证明补录四页无横向滚动；
  legacy `/index.html` 本轮仅作源码/DOM 审计。可见焦点和 reduced-motion 仍以已有公开回归为证据。
- 主要问题从“能否显示”转为“移动首屏是否仍保留对象、状态和下一步”；简单纵向堆叠不足以满足高频运营。
- 后续合同需继续覆盖长中文名、Dialog 焦点、aria-live、错误替换 loading、终态动作和键盘操作。

## 6. 后续定向外部研究问题

本节仅列研究问题，不在本阶段搜索、选型或复制案例。研究必须由上述内部问题驱动。

1. 成熟企业内容/生产工作台如何在稳定一级导航与项目阶段导航之间分工？
2. 多项目、多商品场景如何展示可扫描的阶段、阻断和负责人，而不伪造后端没有的汇总数据？
3. 高风险串行生产如何以业务状态为主，同时完整保留基础设施、attempt 和审计证据？
4. 已交付终态如何区分“查看结果”“再次交付”“返工产生新生产周期”，避免重复主操作？
5. 中文高密度工作台如何处理长商品名、状态标签、筛选和移动端对象切换？
6. 素材库如何按类型、用途、授权与关联关系组织，同时适配图片、人物和视频？
7. 管理员目录管理与普通运营对象选择如何在 IA 和权限上分层？
8. 加载、权限、业务阻断、技术失败与异步处理中，哪些错误恢复模式能保持单一推荐下一步？

研究输出必须说明适用条件、与本项目合同的冲突、采纳或拒绝理由；不得照搬品牌资产、页面结构或未经验证的批量操作。

## 7. 后续设计合同输入与验收门禁

下一份设计合同至少需要以下输入：

- 本审计的 P1/P2 问题、角色任务模型和页面证据；
- 定向研究中经本项目约束筛选后的模式与拒绝理由；
- 当前 API 能提供的状态、汇总、素材关联和权限事实；
- QC/人工审核、预检/方案批准、生产串行门禁、Works 深链/组织授权等不可破坏合同；
- 1440/768/390、长中文、键盘、reduced-motion、错误恢复和终态恢复矩阵。

设计合同通过 acceptance gate 前，不得开始全局重构。合同验收至少要求：

1. 稳定 IA 能覆盖企业入口、项目阶段、素材、作品和管理员能力，并解释 legacy 边界；
2. 每页每个关键状态只有一个推荐下一步，危险/次级/不可用动作语义明确；
3. 中文词汇表区分业务状态、自动检查、人工批准和技术详情；
4. Production 保留严格逐单时序，Works 保留深链与组织授权，任何批量动作都有安全合同；
5. Assets 的类型/用途/关联方案不伪造现有 API 不提供的数据；
6. 提供可串行、可独立 Review、可回滚的实施切片与公开浏览器验收。
